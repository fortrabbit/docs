## Create the app

Create an app with Drupal as the software and connect the GitHub repository. The [software template](/1.platform/03.concepts/05.software-templates.md) then sets:

- the [root path](/1.platform/07.settings/12.root-path.md) `web`
- `composer install` as the [build command](/1.platform/06.deployment/03.build-commands.md)
- `drush deploy` as the [post-deploy command](/1.platform/06.deployment/04.post-deploy-commands.md)
- `web/sites/default/files` as an [exclude pattern](/1.platform/06.deployment/10.exclude-patterns.md), so uploads survive deployments
- the ENV vars below

Choose Drupal, not General PHP or another software. Without the Drupal template, the `DB_*` variables and `DRUPAL_HASH_SALT` are missing, and the [settings.php block](/2.guides/8.drupal/01.install.md#settingsphp) finds no database.

:BlockLink{title="Change the root path for {{app-name}} / {{app-env-name}}" path="/environments/{{app-env-id}}/settings/rootpath"}

## First deployment

Connecting the repository deploys the code. The site does not run yet: the database is empty. Push the local database and files up, as in [database up](/2.guides/8.drupal/03.database.md#database-up) and [files up](/2.guides/8.drupal/04.files.md#files-up):

```shell
ddev export-db --file=local.sql.gz
frbit db push local.sql.gz {{app-env-id}}
frbit files push web/sites/default/files -e {{app-env-id}}
```

Or install a fresh site over SSH with `frbit ssh {{app-env-id}} -- vendor/bin/drush site:install`. From then on, every push to the branch deploys.

## Drush deploy

`drush deploy` runs database updates, imports the configuration from `config/sync` and rebuilds the caches. The template wraps it, so it skips while Drush is missing or no site is installed yet:

```shell
if vendor/bin/drush status --field=bootstrap 2>/dev/null | grep -q Successful; then vendor/bin/drush deploy; else echo 'No drush or no installed Drupal site, skipping drush deploy'; fi
```

A configuration change follows the Drupal way: change it locally, export, commit, push.

```shell
ddev drush config:export -y
git add config/sync
git commit -m "Update config"
git push
```

`drush deploy` refuses an empty sync folder, and the deployment fails. Export and commit the configuration before the first deployment that runs it.

## Drush over SSH

Run Drush on the environment with `frbit ssh`, or over plain [SSH](/1.platform/05.code-access/03.ssh.md). Call `vendor/bin/drush` directly, not through `php`: it is a shell script.

```shell
frbit ssh {{app-env-id}} -- vendor/bin/drush status
```

## ENV vars

The template sets the `DB_*` variables from the [MySQL component](/1.platform/09.components/02.mysql.md) and a random `DRUPAL_HASH_SALT`. The [settings.php block](/2.guides/8.drupal/01.install.md#settingsphp) reads them.

## Logs

Drupal keeps its own log at `/admin/reports/dblog`. PHP errors show up in the [logs](/1.platform/07.settings/25.logs.md) of the dashboard.
