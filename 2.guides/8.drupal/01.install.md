## Install and deploy run down

1. **Install Drupal locally** _← you are here_
2. [Deploy Drupal to fortrabbit](/2.guides/8.drupal/02.deployment.md)
3. [Database syncing](/2.guides/8.drupal/03.database.md)
4. [Files syncing](/2.guides/8.drupal/04.files.md)

## Get ready

- [DDEV](/4.integrations/01.local-development/02.ddev.md) installed and running. Another local setup works too, the commands then drop the `ddev` prefix.
- The [frbit CLI](/1.platform/04.automation/03.cli.md) installed and signed in, for the database and files syncing later on.
- Skip to [settings.php](#settingsphp) when a Drupal project already runs locally.

## Create the project

Configure DDEV for Drupal, with the PHP version of the fortrabbit environment, then let Composer create the project:

```shell
mkdir my-drupal-site && cd my-drupal-site
ddev config --project-type=drupal11 --docroot=web --php-version=8.5
ddev start
ddev composer create-project drupal/recommended-project
ddev composer require drush/drush
```

Drush ships with every deployment this way. The fortrabbit software template runs it after each deployment, see [Drush deploy](/2.guides/8.drupal/02.deployment.md#drush-deploy).

## settings.php

Edit `web/sites/default/settings.php` before installing Drupal. Add this block above the DDEV include near the end of the file:

```php
$settings['config_sync_directory'] = '../config/sync';

if (getenv('DB_HOST')) {
  $databases['default']['default'] = [
    'driver' => 'mysql',
    'database' => getenv('DB_DATABASE'),
    'username' => getenv('DB_USERNAME'),
    'password' => getenv('DB_PASSWORD'),
    'host' => getenv('DB_HOST'),
    'port' => getenv('DB_PORT') ?: '3306',
    'prefix' => '',
    'collation' => 'utf8mb4_general_ci',
  ];
  $settings['hash_salt'] = getenv('DRUPAL_HASH_SALT');
}
```

- The config sync folder sits outside the web root and goes into Git. Without that line, DDEV puts it into `web/sites/default/files/sync`, which is neither committed nor deployed.
- The `DB_*` variables and `DRUPAL_HASH_SALT` exist on fortrabbit only, see [ENV vars](/2.guides/8.drupal/02.deployment.md#env-vars). Locally, DDEV's own `settings.ddev.php` connects the database.

## Install Drupal

Install the site with Drush, or open `ddev launch` and click through the installer. Then export the configuration:

```shell
ddev drush site:install standard --account-name=admin -y
ddev drush config:export -y
```

## Git ignores

`drupal/recommended-project` ships no `.gitignore`. Create one in the project root:

```gitignore
/vendor/
/web/core/
/web/modules/contrib/
/web/themes/contrib/
/web/profiles/contrib/
/web/libraries/
/web/sites/*/files/
/web/sites/*/settings.local.php
/web/sites/*/settings.ddev.php
*.sql.gz
```

The last line keeps database dumps from `frbit db pull` out of the repo. GitHub has a longer [Drupal.gitignore](https://github.com/github/gitignore/blob/main/Drupal.gitignore).

## Push to GitHub

Put the project on GitHub, here with the [GitHub CLI](/4.integrations/07.git-clients/02.gh-cli.md):

```shell
git init
git add .
git commit -m "Init"
gh repo create --private --source=. --push
```
