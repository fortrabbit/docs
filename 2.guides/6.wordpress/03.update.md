WordPress installs minor releases on its own. For other updates, wp-admin shows an update button, or [WP-CLI](/2.guides/6.wordpress/02.tune.md#using-the-wp-cli) runs `wp core update`. A [Bedrock](https://roots.io/bedrock/) setup updates through Composer instead. See [updating WordPress](https://wordpress.org/documentation/article/updating-wordpress/).

## Update locally first

Test updates in a [local development environment](/4.integrations/01.local-development/01.intro.md) or a [staging environment](/3.dev/15.learn/03.staging-environments.md) first. A core update can change the database schema. When only the files are updated, wp-admin asks to update the database.

## Parallel updates

Run each update in every environment, local first, then production, so the versions and database schemas match.

## Updating plugins and themes

Plugins and themes follow the same order. Outdated plugins are the most common way into a WordPress site, see [secure WordPress](/2.guides/6.wordpress/04.security.md).

## Keeping your environments in sync

Editors add content in production, so the local database and uploads fall behind. Sync both:

1. For the **database**, check our [MySQL article for import/export](/1.platform/08.mysql/02.export-import/07.intro.md).
2. For the **files** you can either use [SFTP](/1.platform/05.code-access/04.sftp.md) or have a look at [rsync](/3.dev/20.how-to/rsync.md) to synchronize certain folders.

Content usually comes down, code changes go up.
