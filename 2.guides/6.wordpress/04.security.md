WordPress installs minor core releases automatically. Turn on automatic updates for plugins and themes in wp-admin too, see [automatic background updates](https://developer.wordpress.org/advanced-administration/upgrade/upgrading/) and [update WordPress](/2.guides/6.wordpress/03.update.md).

## Protect against bots

Bots attack `wp-login.php` and `xmlrpc.php` all day. Block XML-RPC when no app uses it, and limit the login, for example with [.htaccess rules](/3.dev/21.htaccess/08.block-ip.md) or the [incoming firewall](/1.platform/07.settings/20.firewall-incoming.md).

## Sending e-mails

fortrabbit has no [sendmail](/1.platform/03.concepts/09.limits.md#mailing), so `wp_mail()` needs an SMTP plugin such as [WP Mail SMTP](https://wordpress.org/plugins/wp-mail-smtp/) or [WP SMTP](https://wordpress.org/plugins/wp-smtp/), with a mail account or a [transactional mail provider](/4.integrations/10.transactional-mail/01.intro.md).

## Resetting the wp-admin password

Without working e-mail, "Lost your password?" does not work. Reset the password another way.

The recommended method is [WP-CLI](/2.guides/6.wordpress/02.tune.md#using-the-wp-cli) over an [SSH](/1.platform/05.code-access/03.ssh.md) connection. It hashes the new password with the current WordPress algorithm:

```shell
wp user update admin --user_pass="a-strong-new-password"
```

Replace `admin` with the account's user login or email address.

As a fallback, set the password directly in the database. WordPress accepts an MD5 hash in the `user_pass` column for backward compatibility and re-hashes it with the current algorithm on the next successful login:

1. Connect to the remote MySQL database from local
2. Find the account in the `wp_users` table
3. Set `user_pass` to the MD5 hash of a safe new password
4. Log in to wp-admin, which upgrades the stored hash automatically
