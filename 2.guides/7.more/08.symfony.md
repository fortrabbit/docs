## Install Symfony locally

Set up Symfony in a [local development environment](/4.integrations/01.local-development/01.intro.md), see the [Symfony setup docs](https://symfony.com/doc/current/setup.html). fortrabbit serves PHP with Apache, so add the `.htaccess` rules of the Apache pack, and confirm the Flex recipe with `y`:

```shell
composer require symfony/apache-pack
```

Push the code to a GitHub repository for [Git deployment](/1.platform/06.deployment/01.intro.md), see the [Git intro](/3.dev/15.learn/git-intro.md) if Git is new.

## Software template

The Symfony [software template](/1.platform/03.concepts/05.software-templates.md) sets these values:

:SoftwarePreset{slug="symfony"}

In short:

- The root path `public`
- `APP_ENV=prod`, `APP_DEBUG=false` and a random `APP_SECRET`
- `DATABASE_URL` from the [MySQL component](/1.platform/09.components/02.mysql.md)
- Post deploy commands that clear the cache, install the assets and run the Doctrine migrations
- `/public/uploads` as an [exclude pattern](/1.platform/06.deployment/10.exclude-patterns.md), so uploads survive deployments

With a `package.json` in the repository, the [stack detector](/1.platform/03.concepts/04.stack-detector.md) adds `npm install` and `npm run build` to the build commands. Apps created without the template need these settings by hand: [ENV vars](/1.platform/07.settings/01.env-vars.md), [root path](/1.platform/07.settings/12.root-path.md) and the deployment settings.

## Commands over SSH

Run console commands over [SSH](/1.platform/05.code-access/03.ssh.md), for example to load fixtures:

```shell
$ ssh {{app-env-id}}@ssh.{{region}}.frbit.app 'php bin/console doctrine:fixtures:load'
$ ssh {{app-env-id}}@ssh.{{region}}.frbit.app 'php bin/console cache:clear'
```

## Tailwind

The [TailwindBundle](https://symfony.com/bundles/TailwindBundle/current/index.html) downloads the standalone Tailwind CLI, a binary the build cannot run, see [limits of the build](/1.platform/06.deployment/03.build-commands.md#limits-of-the-build). Install Tailwind through npm instead, for example with [Webpack Encore](https://symfony.com/doc/current/frontend/encore/installation.html):

```shell
composer require symfony/webpack-encore-bundle
npm install -D tailwindcss postcss postcss-loader autoprefixer @tailwindcss/postcss
```

Enable PostCSS in `webpack.config.js`:

```js
    .enablePostCssLoader()
```

Create `postcss.config.js` in the project root:

```js
module.exports = {
  plugins: {
    '@tailwindcss/postcss': {},
    autoprefixer: {},
  },
};
```

And import Tailwind in `assets/styles/app.css`:

```css
@import 'tailwindcss';
@source '../../templates';
```

The build commands then compile it with each deployment.

## Logging

Symfony logs with Monolog. Its default configuration for `prod` writes to `php://stderr`, which shows up in the [logs](/1.platform/07.settings/25.logs.md) of the dashboard. Keep that in `config/packages/monolog.yaml`.

## Sending e-mail

fortrabbit has no [sendmail](/1.platform/03.concepts/09.limits.md#mailing). Configure the Symfony Mailer with the `MAILER_DSN` ENV var, pointing to SMTP or a [transactional mail provider](/4.integrations/10.transactional-mail/01.intro.md), see the [Symfony Mailer docs](https://symfony.com/doc/current/mailer.html).
