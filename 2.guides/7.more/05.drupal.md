## Get ready

It's assumed you've already created a new app and chose Drupal in the [software template](/1.platform/03.concepts/05.software-templates.md). If not: You can do so in the fortrabbit dashboard. You should have a [local PHP development environment](/4.integrations/01.local-development/01.intro.md) running on your local machine. Drupal has good backward compatibility and this guide should work for Drupal 10 and 11. We recommend following the [official Drupal installation guide](https://www.drupal.org/docs/installing-drupal) to install Drupal locally first. Here is an idea how to do it with Composer:

```shell
# Create a new Drupal project with Composer
composer create-project drupal/recommended-project my-drupal-site

# Navigate to the project directory
cd my-drupal-site

# Install Drupal via Composer (alternative method)
composer install
```

We recommend to use DDEV for local development. See their [Drupal quick start](https://docs.ddev.com/en/stable/users/quickstart/#drupal-drupal-11).

## Deployment

Drupal supports Git and Composer workflows. Deploy via GitHub using our [GitHub integration](/1.platform/06.deployment/02.github-app.md) via `git push`. SSH/SFTP code access is also available.

### Git ignores

At the time of writing, it appears that Drupal does not ship with a standard `.gitignore` file. It's suggested to create such a file on the root directory of the project, matching your requirements.

- [drupal.org/project/drupal_cms/issues/3500134](https://www.drupal.org/project/drupal_cms/issues/3500134) - Issue
- [github.com/github/gitignore/blob/main/Drupal.gitignore](https://github.com/github/gitignore/blob/main/Drupal.gitignore) - Example

### Git deployment workflow

1. Set up your local Drupal project with Git
2. Deploy to GitHub
3. Install the [fortrabbit GitHub App](/1.platform/06.deployment/02.github-app.md)
4. Connect your GitHub repository to your fortrabbit app environment
5. Push to deploy automatically

The [build commands](/1.platform/06.deployment/03.build-commands.md) will automatically run `composer install` during deployment when using our Drupal software template.

### Initial deployment steps

1. Create your Drupal project locally
2. Initialize Git and make your initial commit
3. Push your code to your GitHub repository
4. Deploy to fortrabbit via GitHub integration
5. Install Drupal via [SSH](/1.platform/05.code-access/03.ssh.md) with `vendor/bin/drush site:install`, or import an existing database
6. Export the configuration and commit it, see [Drush](#drush) below

## Drush

Drush is the Drupal command line tool. Require it with Composer, so it ships with every deployment:

```shell
composer require drush/drush
```

Call it directly via SSH, not through the PHP interpreter: `vendor/bin/drush` is a shell script.

```shell
ssh {{app-env-id}}@ssh.{{region}}.frbit.app
vendor/bin/drush status
```

### Drush deploy

`drush deploy` runs database updates, imports the configuration and rebuilds caches. The Drupal software template sets it as a [post deploy command](/1.platform/06.deployment/04.post-deploy-commands.md). It is skipped while Drush is missing or the site is not installed yet, so the first deployment of a fresh environment does not fail:

```shell
if vendor/bin/drush status --field=bootstrap 2>/dev/null | grep -q Successful; then vendor/bin/drush deploy; else echo 'No drush or no installed Drupal site, skipping drush deploy'; fi
```

`drush deploy` imports the configuration from the sync directory. It refuses an empty sync directory, and the deployment fails. Export the configuration locally and commit it:

```shell
vendor/bin/drush config:export
git add config/sync
```

## Files and uploads

Drupal stores uploaded files in the `web/sites/default/files` directory by default. The software template excludes that directory from [deployments](/1.platform/06.deployment/10.exclude-patterns.md), so uploads persist when new code is deployed.

### Using rsync for file management

You can use [rsync](/3.dev/20.how-to/rsync.md) to sync files between your local development and fortrabbit:

```shell
# Download files from fortrabbit to local
rsync -av {{app-env-id}}@ssh.{{region}}.frbit.app:web/sites/default/files/ ./web/sites/default/files/

# Upload files from local to fortrabbit
rsync -av ./web/sites/default/files/ {{app-env-id}}@ssh.{{region}}.frbit.app:web/sites/default/files/
```

## Manual database settings

Drupal reads the database connection from `web/sites/default/settings.php`. The software template sets the `DB_*` environment variables. Read them in `settings.php`:

```php
if (getenv('DB_HOST')) {
  $databases['default']['default'] = [
    'driver' => 'mysql',
    'database' => getenv('DB_DATABASE'),
    'username' => getenv('DB_USERNAME'),
    'password' => getenv('DB_PASSWORD'),
    'host' => getenv('DB_HOST'),
    'port' => getenv('DB_PORT') ?: '3306',
    'prefix' => '',
    'collation' => 'utf8mb4_general_ci',
  ];
  $settings['hash_salt'] = getenv('DRUPAL_HASH_SALT');
  $settings['config_sync_directory'] = '../config/sync';
}
```

For your local development setup, you can create a `settings.local.php` file with your local database credentials.
