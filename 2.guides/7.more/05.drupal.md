## Get ready

Create an app with Drupal as the software, so the [software template](/1.platform/03.concepts/05.software-templates.md) applies. The template covers Drupal 11; Drupal 10 gets the platform defaults and needs the settings below by hand. Install Drupal in a [local development environment](/4.integrations/01.local-development/01.intro.md) first, see the [Drupal installation guide](https://www.drupal.org/docs/installing-drupal):

```shell
# Create a new Drupal project with Composer
composer create-project drupal/recommended-project my-drupal-site

# Navigate to the project directory
cd my-drupal-site

```

[DDEV](/4.integrations/01.local-development/02.ddev.md) has a [Drupal quickstart](https://docs.ddev.com/en/stable/users/quickstart/).

## Root path

The template sets the [root path](/1.platform/07.settings/12.root-path.md) to `web`.

## Deployment

Drupal deploys with Composer and Git through the [GitHub App](/1.platform/06.deployment/02.github-app.md). The [build commands](/1.platform/06.deployment/03.build-commands.md) run `composer install`.

### Git ignores

`drupal/recommended-project` ships no `.gitignore`. Create one in the project root that keeps out at least `vendor`, `web/core`, `web/modules/contrib` and `web/sites/*/files`:

- [drupal.org/project/drupal_cms/issues/3500134](https://www.drupal.org/project/drupal_cms/issues/3500134) - Issue
- [github.com/github/gitignore/blob/main/Drupal.gitignore](https://github.com/github/gitignore/blob/main/Drupal.gitignore) - Example

### First deployment

1. Commit the local project and push it to GitHub.
2. Connect the repository to the app; the push deploys.
3. Install Drupal over [SSH](/1.platform/05.code-access/03.ssh.md) with `vendor/bin/drush site:install`, or [import](/1.platform/08.mysql/02.export-import/07.intro.md) an existing database.
4. Export the configuration and commit it, see [Drush](#drush).

## Drush

Drush is the Drupal command line tool. Require it with Composer, so it ships with every deployment:

```shell
composer require drush/drush
```

Call it directly via SSH, not through the PHP interpreter: `vendor/bin/drush` is a shell script.

```shell
ssh {{app-env-id}}@ssh.{{region}}.frbit.app
vendor/bin/drush status
```

### Drush deploy

`drush deploy` runs database updates, imports the configuration and rebuilds caches. The Drupal software template sets it as a [post deploy command](/1.platform/06.deployment/04.post-deploy-commands.md). It is skipped while Drush is missing or the site is not installed yet, so the first deployment of a fresh environment does not fail:

```shell
if vendor/bin/drush status --field=bootstrap 2>/dev/null | grep -q Successful; then vendor/bin/drush deploy; else echo 'No drush or no installed Drupal site, skipping drush deploy'; fi
```

`drush deploy` imports the configuration from the sync directory. It refuses an empty sync directory, and the deployment fails. Export the configuration locally and commit it:

```shell
vendor/bin/drush config:export
git add config/sync
```

## Files and uploads

Drupal stores uploads in `web/sites/default/files`. The template [excludes](/1.platform/06.deployment/10.exclude-patterns.md) that folder from deployments, so uploads persist.

### Using rsync for file management

Sync the files with [rsync](/3.dev/20.how-to/rsync.md):

```shell
# Download files from fortrabbit to local
rsync -av {{app-env-id}}@ssh.{{region}}.frbit.app:web/sites/default/files/ ./web/sites/default/files/

# Upload files from local to fortrabbit
rsync -av ./web/sites/default/files/ {{app-env-id}}@ssh.{{region}}.frbit.app:web/sites/default/files/
```

## Logs

Drupal keeps its own log at `/admin/reports/dblog`. PHP errors show up in the [logs](/1.platform/07.settings/25.logs.md) of the dashboard.

## Database and ENV vars

The template sets the `DB_*` variables from the [MySQL component](/1.platform/09.components/02.mysql.md) and a random `DRUPAL_HASH_SALT`. Drupal reads its database connection from `web/sites/default/settings.php`, so read the variables there:

```php
if (getenv('DB_HOST')) {
  $databases['default']['default'] = [
    'driver' => 'mysql',
    'database' => getenv('DB_DATABASE'),
    'username' => getenv('DB_USERNAME'),
    'password' => getenv('DB_PASSWORD'),
    'host' => getenv('DB_HOST'),
    'port' => getenv('DB_PORT') ?: '3306',
    'prefix' => '',
    'collation' => 'utf8mb4_general_ci',
  ];
  $settings['hash_salt'] = getenv('DRUPAL_HASH_SALT');
  $settings['config_sync_directory'] = '../config/sync';
}
```

Keep the local credentials in a `settings.local.php`.
