## Install plugins from the control panel

The plugin store in the local control panel finds, installs and buys plugins in one place:

1. Open the control panel of the local Craft installation
2. Go to the plugin store
3. Search, install and activate the plugin

The plugin store adds the plugin to `composer.json`. Commit `composer.json`, `composer.lock` and `config/project`, then deploy: the build runs `composer install` and the post-deploy commands apply the project config, which installs the plugin on fortrabbit. On fortrabbit, `CRAFT_ALLOW_ADMIN_CHANGES=false` makes the plugin store read-only and locks the plugin versions, see [production settings](/2.guides/3.craft-cms/08.production-settings.md).

## Install plugins in the terminal

```shell
composer require {vendor/package-name}
php craft plugin/install {plugin-handle}
```

Update plugins like Craft itself, see [updating Craft CMS](/2.guides/3.craft-cms/12.updating.md).

## Image optimization plugins

Image transforms cost CPU time, and so do optimizers like jpegoptim or optipng. These tools are available in [jobs](/1.platform/09.components/07.jobs.md), not in the web environment. Run them in a worker job, the way [image transforms](/2.guides/3.craft-cms/16.image-transforms.md) moves transforms there.

## Plugins and performance

Each plugin adds code to every request, and some add database queries or queue jobs. Prefer few, small plugins. See [Craft CMS performance](/2.guides/3.craft-cms/11.performance.md).

## Plugins and updates

A plugin without a release for a new Craft version blocks the Craft upgrade until the plugin catches up. Fewer plugins mean fewer of those waits.
