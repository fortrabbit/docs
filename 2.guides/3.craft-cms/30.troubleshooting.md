## Errors after the first deployment

- **Mismatching security key**: the software template generates a random `CRAFT_SECURITY_KEY`. Data encrypted locally can't be read with it. Copy the local key into the [ENV vars](/2.guides/3.craft-cms/07.env-vars.md) of the environment when importing the local database.
- **No database connection**: Craft on fortrabbit reads the database settings from the ENV vars of the environment, never from the local `.env` file. Check the `CRAFT_DB_*` values against the [template](/2.guides/3.craft-cms/07.env-vars.md).
- **Missing table prefix**: a local table prefix needs the same `CRAFT_DB_TABLE_PREFIX` on fortrabbit.
- **Missing .htaccess file**: SFTP clients often hide dot files. Upload `web/.htaccess` with the rest of the project.

## Show error details

On fortrabbit, Craft shows a generic error page instead of the exception. Read the error in the [logs](/1.platform/07.settings/25.logs.md) of the environment, or set `CRAFT_DEV_MODE=true` on an environment that is not public and back to `false` afterwards, see [production settings](/2.guides/3.craft-cms/08.production-settings.md).

## Large uploads fail

The smallest of three limits caps the upload size, Craft's [`maxUploadFileSize`](https://craftcms.com/docs/5.x/reference/config/general.html#maxuploadfilesize) setting or the PHP settings `upload_max_filesize` and `post_max_size`. Change the PHP ones in the [PHP settings](/1.platform/07.settings/06.php.md) of the environment. A large image can also run out of memory while Craft creates its [transforms](/2.guides/3.craft-cms/16.image-transforms.md).
