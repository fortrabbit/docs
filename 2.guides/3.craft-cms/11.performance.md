## About Craft CMS performance

Most slow Craft CMS sites in our support share a few causes. Start by finding where the time goes: the [metrics and logs](/3.dev/02.performance/04.monitoring.md) of the environment show whether PHP, memory or the database is the bottleneck. The general [performance section](/3.dev/02.performance/01.intro.md) covers what applies to any PHP app, including [PHP processes](/3.dev/02.performance/06.php-processes.md) and [scaling](/3.dev/02.performance/11.scaling.md).

## Common causes

| Symptom | Likely cause | Fix |
| -- | -- | -- |
| 504 on image upload or first page view | Image transforms | [Image transforms](/2.guides/3.craft-cms/16.image-transforms.md) |
| Slow pages, many queries | Element queries | [Database queries](/2.guides/3.craft-cms/17.database-queries.md) |
| Site slow while editors work | Queue in web requests | [Queue jobs](/2.guides/3.craft-cms/15.queueing.md) |
| Memory kills | Transforms, bulk updates | [Out of memory](/3.dev/02.performance/10.out-of-memory.md) |
| High disk I/O | Cache without key | [Caching](/2.guides/3.craft-cms/18.caching.md) |
| Load from bots | Uncached 404 pages | [Caching](/2.guides/3.craft-cms/18.caching.md) |

## Blocking PHP requests

A [PHP process](/3.dev/02.performance/06.php-processes.md) is busy as long as it is executing. When all of them are busy, the site stops answering. Examples from support:

- A plugin queries an external service in a blocking way and the answer takes too long.
- The database is overwhelmed by too many or too expensive queries.
- Image transforms or the queue run in the PHP processes that serve the site.

## Dev mode in production

Keep `CRAFT_DEV_MODE=false` on fortrabbit, as the software template sets it. In dev mode, Craft logs more and writes verbose log files, which costs time on every request. See [production settings](/2.guides/3.craft-cms/08.production-settings.md).
