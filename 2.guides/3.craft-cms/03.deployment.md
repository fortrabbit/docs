## Git deployment

With the repository connected to the app, every `git push` to the deployment branch deploys Craft CMS to fortrabbit. The deploy button in the dashboard starts a deployment of the latest commit as well. See the [deployment intro](/1.platform/06.deployment/01.intro.md) for how it works.

## Deployment configuration

The [stack detector](/1.platform/03.concepts/04.stack-detector.md) and the Craft CMS [software template](/1.platform/03.concepts/05.software-templates.md) set up the deployment when the app is created. Change it later in the deployment settings of the environment or with a [deploy file](/1.platform/06.deployment/06.deploy-file.md).

### Build commands

[Build commands](/1.platform/06.deployment/03.build-commands.md) run before the new code goes live:

```shell
composer install --no-dev --prefer-dist --no-interaction --no-ansi --no-progress
# Only with a package.json and a lock file in the repository
npm install
npm run build
```

### Post-deploy commands

[Post-deploy commands](/1.platform/06.deployment/04.post-deploy-commands.md) run once the new code is live. They apply database migrations and the project config, then clear the caches:

```shell
php craft migrate/all
php craft project-config/apply
php craft clear-caches/all
```

### Deployment strategy

Craft CMS apps use the [merge strategy](/1.platform/06.deployment/08.strategy.md#merge-strategy): files on the environment that are not in the repository stay, so asset volumes survive a deployment wherever they sit. A [replace pattern](/1.platform/06.deployment/15.replace-patterns.md) for `/config/project` makes sure project config files deleted from the repository are deleted on the environment too.

The [replace strategy](/1.platform/06.deployment/08.strategy.md#replace-strategy) also works, with an [exclude pattern](/1.platform/06.deployment/10.exclude-patterns.md) for every asset volume.
