## Assets and git

Craft CMS assets are uploaded files, mostly images, stored in volumes, see the [Craft docs on assets](https://craftcms.com/docs/5.x/reference/element-types/assets.html). They stay out of git: files uploaded on the environment never reach the repository, because [git deployment only goes up](/1.platform/06.deployment/01.intro.md#git-only-syncs-up).

When Craft creates the folder of a local filesystem, it adds a `.gitignore` file to it. For a folder that existed before, add that file by hand:

```gitignore
*
!.gitignore
```

## Sync assets with rsync

[rsync](/3.dev/20.how-to/rsync.md) copies only changed files, in both directions. Replace `uploads` with the folder of the volume:

```shell
# UP: local to fortrabbit
rsync -av ./web/uploads/ {{app-env-id}}@ssh.{{region}}.frbit.app:web/uploads/

# DOWN: fortrabbit to local
rsync -av {{app-env-id}}@ssh.{{region}}.frbit.app:web/uploads/ ./web/uploads/
```

Add `--dry-run` to see what would change first. The [rsync guide](/3.dev/20.how-to/rsync.md) covers excludes and `--delete`.

## Sync assets with SFTP

An [SFTP](/1.platform/05.code-access/04.sftp.md) client works too. Many clients have a sync option that compares local and remote folders.

## Store assets in S3

With the first-party [Amazon S3 plugin](https://plugins.craftcms.com/aws-s3), Craft stores uploads in an S3 bucket instead of the environment's [storage](/1.platform/09.components/03.storage.md), and nothing needs syncing. It adds a service to pay for and set up, so use it for many or large files, not by default.
