## First deployment fails at craft:up

`php artisan craft:up` fails with "Base table or view not found" while Craft is not installed in the database. Import the local database or install Craft over SSH, then deploy again, see [setup](/2.guides/3.craft-cms/40.craft-6/02.setup.md#bring-the-database-up).

## Site shows a 503 page

A failed `craft:up` leaves Laravel's maintenance mode on. Its file sits in `storage/framework/down`, which deployments don't touch, so it stays after the next deployment. Turn it off over [SSH](/1.platform/05.code-access/03.ssh.md):

```shell
ssh {{app-env-id}}@ssh.{{region}}.frbit.app php artisan up
```

## craft:install is cancelled

`php artisan craft:install` asks to confirm the run with `APP_ENV=production` and has no `--force` option. Run it in an interactive SSH session, with `ssh -t`, and confirm with yes.

## Project config validation failed

`craft:install` stops with "Project config validation failed" when `config/craft/project/project.yaml` exists but is empty. A failed first deployment can leave such a file. Delete the folder on the environment and run the install again:

```shell
rm -rf config/craft/project
```

## Show error details

Craft logs errors to the [logs](/1.platform/07.settings/25.logs.md) of the environment, with `LOG_STACK=stderr` from the [ENV vars](/2.guides/3.craft-cms/40.craft-6/04.env-vars.md). Set `APP_DEBUG=true` only on an environment that is not public, and back to `false` afterwards.
