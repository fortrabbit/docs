## Queue

Craft CMS 6 queues long-running tasks such as [image transforms](/3.dev/02.performance/12.image-transforms.md), and with Craft 6 also password reset and email verification mails. The queue uses Laravel's `database` driver and the `jobs` table, which the post-deploy command `php artisan migrate --force` creates.

By default, Craft runs the queue through web requests, in the PHP processes that serve the site. Run it in a [worker](/1.platform/30.jobs/03.workers.md) instead:

1. Book the [jobs component](/1.platform/09.components/07.jobs.md)
2. Add a worker with this command:

   ```shell
   php artisan queue:work --sleep=3 --tries=3 --max-time=3600
   ```

3. Turn off the web-based queue runner in `config/craft/general.php`:

   ```php
   ->runQueueAutomatically(false)
   ```

`--max-time` restarts the worker every hour, which frees memory. See the [Laravel queue guide](/2.guides/2.laravel/07.queues-scheduler.md#queue) for the options.

## Scheduler

Craft CMS 6 registers tasks with Laravel's scheduler. On Craft Pro, `craft:publish-releases` publishes scheduled releases every minute, so a Pro site needs the cron job. On Craft Solo, Craft schedules nothing, and the cron job is only needed for scheduled tasks of the project itself. Add a [cron job](/1.platform/30.jobs/02.crons.md) that runs every minute:

```shell
php artisan schedule:run
```

`php artisan schedule:list` shows the registered tasks. The [Laravel scheduler notes](/2.guides/2.laravel/07.queues-scheduler.md#scheduler) on `runInBackground()` and `withoutOverlapping()` apply to Craft 6 too.

The worker and the cron job are two jobs. Book a [Jobs](/1.platform/09.components/07.jobs.md) plan that holds two.
