## Volumes on Laravel disks

Craft CMS 6 drops its own filesystems. A volume stores its files on a Laravel disk from `config/filesystems.php`, chosen in the volume settings in the Control Panel.

Use the `public` disk of the skeleton. It stores files in `storage/app/public`, and `/storage` is excluded from [deployments](/2.guides/3.craft-cms/40.craft-6/03.deployment.md), so uploads survive every deployment. Give each volume its own subpath, such as `uploads`.

## The storage link

The `public` disk serves files under `https://…/storage/`, through the `public/storage` symlink. The replace strategy deletes that link on every deployment, so the post-deploy commands create it again:

```shell
php artisan storage:link --force
```

Without it, uploaded images return 404 after a deployment. Add the command to the post-deploy commands of an app created before the template had it.

## Sync assets with rsync

Uploads stay out of git. Copy them with [rsync](/3.dev/20.how-to/rsync.md):

```shell
# UP: local to fortrabbit
rsync -av ./storage/app/public/ {{app-env-id}}@ssh.{{region}}.frbit.app:storage/app/public/

# DOWN: fortrabbit to local
rsync -av {{app-env-id}}@ssh.{{region}}.frbit.app:storage/app/public/ ./storage/app/public/
```

Add `--dry-run` to see what would change first.

## Store assets in S3

The `s3` disk of the skeleton reads `AWS_*` [ENV vars](/1.platform/07.settings/01.env-vars.md) and needs the `league/flysystem-aws-s3-v3` package. Uploads then go to the bucket instead of the environment's [storage](/1.platform/09.components/03.storage.md). It adds a service to pay for and set up, so use it for many or large files. See [Laravel's filesystem docs](https://laravel.com/docs/filesystem#amazon-s3-compatible-filesystems).
