## Working with the panel

Editors manage content in the browser with the Kirby panel. Its users live in `site/accounts`, which Kirby keeps out of Git, so local users do not reach fortrabbit. Create the users on the server, and add `/site/accounts` and `/site/sessions` as [exclude patterns](/1.platform/06.deployment/10.exclude-patterns.md), or each Git deployment deletes them, see [Git and rsync](/2.guides/4.kirby/03.git-and-rsync.md#deployment-settings).

### Setup panel

Kirby blocks the panel installation on public servers, see [create your first account](https://getkirby.com/docs/guide/quickstart#create-your-first-account). To create the first user on fortrabbit, enable the [`panel.install` option](https://getkirby.com/docs/reference/system/options/panel#allow-the-panel-to-be-installed-on-a-remote-server) for that step, then turn it off again.

## Updating Kirby

Update locally first: run `composer update` in the project folder, test, then commit `composer.lock` and `git push`.

## Caching

Turn on the page cache of Kirby in the config file. The template empties it after each deployment.

```php
// /site/config/config.php
return [
  'cache' => [
    'pages' => [
      'active' => true,
    ]
  ]
];
```

Create the file if it does not exist. See the [Kirby cache docs](https://getkirby.com/docs/guide/cache).

## Sending mails

fortrabbit has no [sendmail](/1.platform/03.concepts/09.limits.md#mailing). Configure the [email transport](https://getkirby.com/docs/guide/emails) of Kirby for SMTP, with a mail account or a [transactional mail provider](/4.integrations/10.transactional-mail/01.intro.md).
