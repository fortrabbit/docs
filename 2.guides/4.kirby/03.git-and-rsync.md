## Get ready

- A [local development environment](/4.integrations/01.local-development/01.intro.md) with [Kirby installed](/2.guides/4.kirby/01.install.md)
- Accounts on fortrabbit and GitHub
- The [fortrabbit GitHub App](/1.platform/06.deployment/02.github-app.md) installed on GitHub

## Keep content out of Git

Add these rules to `.gitignore` in the project root:

```shell
# .gitignore

# Kirby itself, managed by composer
/kirby

# Composer, managed
/vendor

# To be synced by rsync not Git
# Can also be included, to keep an extra copy
# Will not be deployed (default exclude patterns)
/content
```

Code then goes by Git, content by rsync. To keep a copy of the content in Git, leave `/content` out of `.gitignore`: the exclude patterns still keep deployments from overwriting it.

## Init Git and add GitHub

Create a Git repository and push it to GitHub, for example with the [GitHub CLI](/4.integrations/07.git-clients/02.gh-cli.md):

```shell
# Setup local git repo
$ git init
$ git add -A
$ git commit -am 'Init'

# GitHub CLI to create/connect remote Git repo
$ gh repo new
# Follow the steps
# Push an existing local repository to github.com
# Add as remote and assign current branch as 'origin'
```

The repository now exists on GitHub. From here on, `git add`, `git commit` and `git push` send changes.

## Connect your GitHub repo with fortrabbit

Create an app on fortrabbit:

:BlockLink{title="Create a new (free trial) app" path="/new/app"}

Choose Kirby as the software and the repository for Git deployment, then start the first deployment. The site shows errors until the content arrives in the next step. An existing app connects the repository in its settings.

### Deployment settings

:BlockLink{title="Deployment settings for {{app-name}} / {{app-env-name}}" path="/environments/{{app-env-id}}/deployment"}

The Kirby [software template](/1.platform/03.concepts/05.software-templates.md) sets the [replace strategy](/1.platform/06.deployment/08.strategy.md) and excludes `content`, `media` and the panel accounts and sessions, so deployments leave them alone. The [Composerkit](/2.guides/4.kirby/01.install.md#kirby-starter-kits) also needs the [root path](/1.platform/07.settings/12.root-path.md) `public`.

Environments created before October 2026 lack the two panel folders. Check the [exclude patterns](/1.platform/06.deployment/10.exclude-patterns.md): without them, every deployment deletes the panel users created on the server:

```plain
/site/accounts
/site/sessions
```

## Synchronize contents with rsync

Git deploys templates, config and the Composer dependencies. The content goes separately, with [rsync](/3.dev/20.how-to/rsync.md). From the project folder:

```shell
# SYNC UP: from local content folder and its files to remote
$ rsync -av ./content/ {{app-env-id}}@ssh.{{region}}.frbit.app:content/
```

Down, to get edits made in the panel on the server:

```bash
# SYNC DOWN: from files from remote content folder to local folder
$ rsync -av {{app-env-id}}@ssh.{{region}}.frbit.app:content/ ./content/
```

[SFTP](/1.platform/05.code-access/04.sftp.md) works for the `content` folder too.

## Going forward

From now on, `git push` [deploys](/1.platform/10.objects/11.deployment.md) code changes, and rsync moves content.
