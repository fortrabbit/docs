## Get ready

- Have a [local development environment](/4.integrations/01.local-development/01.intro.md) with PHP and a web server ready.
- Have [Statamic installed and running locally](/2.guides/5.statamic/01.install.md).

## Deployment considerations

Like [Grav](/2.guides/7.more/07.grav.md) and [Kirby](/2.guides/4.kirby/index.md), Statamic stores content as files. Built on Laravel, it also uses [Composer](/3.dev/15.learn/02.composer.md). That makes both file sync and Git deployment work.

With content in a database, book the [MySQL component](/1.platform/09.components/02.mysql.md) and move the data with [export and import](/1.platform/08.mysql/02.export-import/07.intro.md).

## Deployment options

### 1 - SFTP upload

Upload all contents of your local Statamic folder - including the hidden `.htaccess` file and the `vendor` folder — into the `www` directory of the environment. A good starting point if you are new to web development, but consider moving to rsync for anything recurring.

### 2 - rsync

A scriptable command-line flow that works in both directions: push template and config changes up, pull content down. Easy to automate with AI agents. See the [general rsync article](/3.dev/20.how-to/rsync.md). A good fit for solo projects and quick demos.

### 3 - Git + rsync

The most advanced option, suited for team projects. Manage code with Git for revision history and deployment automation (composer install, cache clearing, migrations); sync content separately with rsync. See [Git + rsync deployment for Statamic](/2.guides/5.statamic/03.deploy-git-rsync.md).

### 4 - Git only

Code and content both live in the repository, and every deployment replaces the content on the environment with the state in git. Content edited online is lost unless it is committed first, so edit content locally. See [content in git](/2.guides/5.statamic/03.deploy-git-rsync.md#content-in-git).
