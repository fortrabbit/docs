## PHP 7.4 to 8.1 come later

PHP 8.2 to 8.5 are available. PHP 7.4, 8.0 and 8.1 are planned as [legacy PHP versions](/1.platform/07.settings/06.php.md#legacy-php-versions) with a monthly fee. Extensions, ini settings and the timezone changed too, see [PHP changes](/1.platform/01.new/5.changes/3.php.md).

## SSH keys only

Sorry, username/password is no longer an option to connect via SSH or SFTP. Please use more secure and more convenient SSH key authentication. Issues with username/password authentication have been the source of many support requests.

## No horizontal scaling

There is no horizontal scaling any more, but higher vertical scaling to cover similar workloads. To achieve this we went a long mile, but it was an important goal, the two stacks have been a barrier.

## No object storage

The new platform currently does not have S3 like asset storage. We may add it later. Larger web storage plans are available.

## No memcache

Memcache is not available on the new platform. A key-value store based on Valkey is planned.

## No Craft Copy

[Craft Copy](https://github.com/fortrabbit/craft-copy), the Craft CMS plugin behind `craft copy/all/up`, works on the old platform only. It will not be ported to the new platform. Each of its jobs has a replacement:

| Craft Copy                   | New platform                                                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `copy/setup`                 | [Craft CMS software template](/1.platform/03.concepts/05.software-templates.md), detected when the app is created |
| `copy/code/up`               | `git push` with [GitHub deployment](/1.platform/06.deployment/02.github-app.md), or `frbit environments deploy`   |
| `copy/db/up`, `copy/db/down` | [Craft database](/2.guides/3.craft-cms/04.database.md) with mysqldump over SSH                                    |
| `copy/volumes/up`, `/down`   | [Craft assets](/2.guides/3.craft-cms/05.assets.md) with rsync                                                     |
| Migrations after deploy      | [Post deploy commands](/1.platform/06.deployment/04.post-deploy-commands.md)                                      |
| Config file cleanup          | [Replace patterns](/1.platform/06.deployment/15.replace-patterns.md)                                              |

The closest thing to `craft copy/all/down` is a coding agent with the [fortrabbit agent skills](/1.platform/04.automation/04.agent-skills.md). Ask it to "pull the production database and the assets". It finds the environment from the git remote, runs mysqldump and rsync over SSH, and asks before it changes anything live. See [agent setup](/1.platform/04.automation/01.agents.md).

Without an agent, the [frbit CLI](/1.platform/04.automation/03.cli.md) deploys, restarts and sets ENV vars from a terminal or CI job.

We aim to be a good Craft CMS hosting provider, as compatible as possible, best without additional plugins required. Maintaining Craft Copy over the years was not always fun, for instance when a minor Craft CMS release introduced changes that required us to rethink critical parts. And fortrabbit no longer hosts the Git repo Craft Copy pushed to.

Craft CMS 6 is based on Laravel, so a port would mean a rewrite anyway.

## No app secrets

App secrets are gone. ENV vars cover most cases, see [alternatives to app secrets](/1.platform/01.new/5.changes/4.app-secrets.md).
