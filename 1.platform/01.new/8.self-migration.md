## Self-service migration

A typical move with Git deployment:

1. Create an account and an app on the new platform.
2. Install the [fortrabbit GitHub App](/1.platform/06.deployment/02.github-app.md) on GitHub.
3. Connect the app to a new or existing GitHub repository.
4. Push the local code base to that repository, which deploys it.
5. Import the database, see [MySQL export and import](/1.platform/08.mysql/02.export-import/07.intro.md).
6. Copy uploads and other content, for example with [rsync](/3.dev/20.how-to/rsync.md).
7. Test the app on its [default domain](/1.platform/13.domains/01.default-domain.md).
8. Point the domain to the new DNS records, see [external domain setup](/1.platform/13.domains/04.external-domain-setup.md).

The same steps apply to apps coming from another host, see [migrate to fortrabbit](/3.dev/20.how-to/migrate-to-fortrabbit.md).

Please :ContactUs{text="contact us"} at any point. We help hands-on and can give a discount during the move.

## Migration program

Apps that stay on the old platform move with the [migration program](/1.platform/01.new/9.migration.md), which starts after the new platform reaches general availability. Each batch is announced by e-mail in advance.
