## About environments

- An environment belongs to an [app](/1.platform/10.objects/01.app.md), and every app has at least one.
- Each environment is a separate hosting setup with its own [settings](/1.platform/07.settings/index.md) and [components](/1.platform/03.concepts/03.components.md), billed on its own.
- Several environments make [staging workflows](/3.dev/15.learn/03.staging-environments.md) possible.

The dashboard names an environment as `{app name} / {environment name}`. Its ID, such as `en-a1b2c3`, never changes.

## Environment maps to git branch

The Git repository belongs to the [app](/1.platform/10.objects/01.app.md), a branch to the environment. [Git deployment](/1.platform/06.deployment/01.intro.md) is optional.

## Environment workflows

Many apps have one environment only. See [project organization](/1.platform/02.get-started/01.project-organization.md).

## Naming an environment

A new environment takes the name of its Git branch, often `main`. The name says nothing about the role: a single environment often serves development first and production later. Change the name in the dashboard.

:BlockLink{title="Change environment name {{app-name}} / {{app-env-name}}" path="/environments/{{app-env-id}}/settings/name"}

## Restarting an environment

A restart can free hanging PHP processes, for example during [504 errors](/3.dev/22.http-status-codes/504.md):

1. Open the environment in the dashboard.
2. Click Restart and confirm.
3. Wait a minute.

The restart covers all services of the environment: PHP, Apache, SSH and jobs. Files and database stay as they are. There is a short downtime. A restart treats the symptom; when it is needed often, see [performance](/3.dev/02.performance/01.intro.md).

## Deleting an environment

Delete an environment in its settings in the dashboard. Its files and database go with it, and deletion cannot be undone, also not by support. See [late payments](/1.platform/12.billing/23.late-payments.md) for when fortrabbit deletes environments.
