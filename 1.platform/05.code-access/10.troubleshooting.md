## SSH key setup

- The public key is uploaded to the fortrabbit account, under SSH keys.
- The same key works elsewhere, for example on GitHub.
- [Code access](/1.platform/05.code-access/01.intro.md) worked before with this key.

See [SSH key setup](/3.dev/15.learn/01.ssh-key-setup.md).

## Verbose mode

Add `-v` to the login command. The output shows which config files and keys are used:

```shell
$ ssh {{app-env-id}}@ssh.{{region}}.frbit.app -v

# OpenSSH_8.4p1, OpenSSL 1.1.1i  8 Dec 2022
# debug1: Reading configuration data /home/user/.ssh/config
# debug1: /home/user/.ssh/config line 6: Applying options for *
# debug1: Reading configuration data /etc/ssh/ssh_config
# debug1: Authenticator provider $SSH_SK_PROVIDER did not resolve; disabling
# … more lines here
```

## Local SSH configuration

Look through `~/.ssh/config` and `~/.ssh/known_hosts`. Delete the entries for fortrabbit hosts to reset the local configuration, see [SSH access](/1.platform/05.code-access/03.ssh.md).

## New environment

A new [environment](/1.platform/10.objects/02.environment.md) takes a minute or two before SSH works. If it still fails after ten minutes, with the key accepted, :ContactUs{text="contact us"}.

## New SSH key

A key added in the dashboard works after a minute or two.

## Password prompt

fortrabbit accepts SSH keys only. A password prompt means one of these:

- The local key has a passphrase, which the prompt asks for.
- The server rejected all keys in `~/.ssh/`. Check the verbose output and the config.

## No connection at all

When the connection hangs or never opens:

- The IP address is blocked after too many connections or failed logins, see [SSH rate limits](/1.platform/05.code-access/11.ssh-rate-limits.md).
- A firewall or VPN on the local network blocks port 22. Test another SSH host, or turn the VPN off.

## Connecting from a container

A container, such as in Docker or DDEV, needs the SSH key too. In DDEV, `ddev auth ssh` makes the local keys available.

## Worked before, fails now

1. Compare the local key with the one in the dashboard.
2. Check that the account still has access to the app, a [collaboration](/1.platform/20.collaboration/1.intro.md) change may have removed it.
3. Check the [SSH rate limits](/1.platform/05.code-access/11.ssh-rate-limits.md).

## Host authenticity warning

The first SSH connection to a fortrabbit host asks to confirm its fingerprint. Type `yes` to store it in `~/.ssh/known_hosts`:

```shell
The authenticity of host '…' can't be established
RSA key fingerprint is …
Are you sure you want to continue connecting (yes/no)?
```

When the fingerprint changes later, SSH refuses to connect. :ContactUs{text="Contact us"} before removing the old entry.
