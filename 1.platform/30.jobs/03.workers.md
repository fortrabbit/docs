## About workers

A worker runs one command non-stop, without a schedule. It waits for work, such as a new entry in a queue, and handles it right away. [Crons](/1.platform/30.jobs/02.crons.md), in contrast, start at fixed times and end. Workers are jobs of the [Jobs component](/1.platform/09.components/07.jobs.md) and run in their own container, separate from the PHP processes that answer web requests. Add them in the dashboard, see [jobs usage](/1.platform/30.jobs/01.usage.md).

## Worker use cases

- Queue workers, such as `php artisan queue:work` in Laravel or the [Craft CMS queue](/2.guides/3.craft-cms/15.queueing.md)
- [Image transforms](/3.dev/02.performance/12.image-transforms.md) and video processing
- Polling an external API

Moving slow tasks from the web request to a worker keeps PHP processes free for visitors, see [PHP processes](/3.dev/02.performance/06.php-processes.md).

## Workers and deployments

Each successful [deployment](/1.platform/06.deployment/01.intro.md) restarts all workers, so they run the latest code. A worker gets the exit signal first, see [graceful shutdown](/1.platform/30.jobs/05.tuning.md#graceful-shutdown).
