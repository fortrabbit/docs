## About crons

A cron job runs a command at fixed times or intervals, without anyone triggering it. The name comes from cron, the Linux scheduler: it reads a table of schedules and commands, the crontab, and starts each command when its time comes. Typical cron jobs:

- Publish scheduled entries
- Send e-mail digests
- Import feeds or sync data from an API
- Generate reports
- Clear caches and old files

## Crontab schedule reference

A schedule has five fields, separated by spaces. A `*` matches every value.

```plain
* * * * *
| | | | |
| | | | Day of week (0-6 | Sun-Sat)
| | | |
| | | Month (1-12)
| | |
| | Day of Month (1-31)
| |
| Hour (0-23)
|
Min (0-59)
```

Examples: `*/5 * * * *` runs every five minutes, `0 3 * * *` every day at 3:00, `0 * * * 1` every hour on Mondays. Times are UTC. [crontab.guru](https://crontab.guru) explains any schedule in words.

## Crons in PHP frameworks

Any PHP script can run as a cron. Laravel comes with its own scheduler: one cron runs `php artisan schedule:run` every minute and starts the tasks that are due, so the schedule lives in the code and in Git. See [Laravel scheduling](/2.guides/2.laravel/05.tune.md#scheduling). For Craft CMS, see [queueing](/2.guides/3.craft-cms/15.queueing.md).

## Crons on fortrabbit

Crons are jobs of the [Jobs component](/1.platform/09.components/07.jobs.md). They run in their own container, separate from the PHP processes that answer web requests. Add them in the dashboard, see [jobs usage](/1.platform/30.jobs/01.usage.md). The output goes to the [jobs logs](/1.platform/07.settings/25.logs.md#jobs-logs).

Each successful [deployment](/1.platform/06.deployment/01.intro.md) restarts all jobs, so crons run the latest code. Crons that start at the same time share the memory of the component, see [jobs tuning](/1.platform/30.jobs/05.tuning.md#overlapping-jobs).
