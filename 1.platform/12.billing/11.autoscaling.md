Turn autoscaling on or off per environment, when creating it or later on the components page.

## Components that autoscale

| Component                                              | Autoscaling | Measured by        |
| ------------------------------------------------------ | ----------- | ------------------ |
| [MySQL](/1.platform/09.components/02.mysql.md)         | ✅ Yes      | Database size      |
| [Storage](/1.platform/09.components/03.storage.md)     | ✅ Yes      | Disk usage         |
| [Traffic](/1.platform/09.components/04.traffic.md)     | ✅ Yes      | Volume of the month |
| [PHP](/1.platform/09.components/01.php.md)             | ❌ No       | -                  |
| [Jobs](/1.platform/09.components/07.jobs.md)           | ❌ No       | -                  |
| [Backups](/1.platform/09.components/05.backups.md)     | ❌ No       | -                  |

## How it works

With autoscaling on, the booked plan is the smallest one. When usage outgrows it, the next larger plan is booked, and when usage drops, the plan goes back down. Storage and MySQL count by the day, see [daily aggregation](/1.platform/12.billing/03.daily-aggregation.md). Traffic grows over the month, and the plan that matches the total of the month applies to the whole month.

## Autoscaling off

Without autoscaling, the price is fixed, and a component stops at the size of its plan:

| Component | When the plan is full |
| -- | -- |
| Storage | The app cannot write files. |
| MySQL | The database accepts no new rows, see [missing INSERT privileges](/1.platform/08.mysql/19.troubleshooting.md#missing-insert-privileges). |
| Traffic | The environment goes offline until the next month. |

The [technical contacts](/1.platform/20.collaboration/4.technical-contact.md) get an e-mail warning shortly before a limit is reached, at most once a month.

## Recommendations

- Keep autoscaling on, with XS plans, to pay for what is used.
- Book a larger plan for a steadier bill.
- Turn autoscaling off for a fixed price, and watch the [metrics](/1.platform/26.metrics/01.intro.md).

The plans grow in wide [tiers](/1.platform/12.billing/30.tiers.md), so most environments stay on the same plan from month to month.

## Usage that grows

Growing usage can mean more visitors, or a problem such as unrotated logs or bots creating content. See why [storage](/1.platform/09.components/03.storage.md#why-storage-grows), [MySQL](/1.platform/09.components/02.mysql.md#why-mysql-storage-grows) and [traffic](/1.platform/09.components/04.traffic.md#why-traffic-grows) grow.

PHP, jobs and backups do not autoscale: their usage gives no clear signal for when to switch plans. :ContactUs{text="Contact us"} if that matters to you.
