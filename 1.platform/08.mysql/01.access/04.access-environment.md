## Automatic software configuration

Configure the database by [ENV vars](/3.dev/19.env-vars/01.intro.md). The [software templates](/1.platform/03.concepts/05.software-templates.md) map the platform variables to the names the software expects, so [Laravel](/2.guides/2.laravel/index.md), [Symfony](/2.guides/7.more/08.symfony.md), [Craft CMS](/2.guides/3.craft-cms/index.md) and [Statamic](/2.guides/5.statamic/index.md) connect without configuration.

```php
// Generic example for illustration purposes
$pdo = new \PDO(
  'mysql:host=' . getenv('FORTRABBIT_DB_HOST') . ';port=' . getenv('FORTRABBIT_DB_PORT') . ';dbname=' . getenv('FORTRABBIT_DB_NAME'),
  getenv('FORTRABBIT_DB_USER'),
  getenv('FORTRABBIT_DB_PASSWORD'),
);
$pdo->query("SELECT * FROM ...");
```

The platform sets these database variables:

- `FORTRABBIT_DB_HOST`
- `FORTRABBIT_DB_PORT`
- `FORTRABBIT_DB_NAME`
- `FORTRABBIT_DB_USER`
- `FORTRABBIT_DB_PASSWORD`

## Manual software configuration

[WordPress](/2.guides/6.wordpress/01.setup.md), for example, reads the database credentials from `wp-config.php`. Enter them there, or read the ENV vars in that file. The dashboard shows the database name, user and password.

:BlockLink{title="Database credentials for {{app-name}} / {{app-env-name}}" path="/environments/{{app-env-id}}/mysql#access"}

## Connecting via SSH session

`mysql` and `mysqldump` are available over [SSH](/1.platform/05.code-access/03.ssh.md). Logged in, run `mysql` to connect to the database.
