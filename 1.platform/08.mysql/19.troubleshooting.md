## Can't connect from local

The database is reachable through an SSH tunnel only. Enter **both the SSH and the MySQL details** in the client. The MySQL settings of the environment in the dashboard show all of them.

:BlockLink{title="See MySQL access for {{app-name}} / {{app-env-name}}" path="/environments/{{app-env-id}}/mysql#access"}

See the [MySQL access guides](/1.platform/08.mysql/01.access/01.intro.md).

## Missing INSERT privileges

When INSERT fails, the grants of the user look like this:

```sql
GRANT SELECT, UPDATE, DELETE, DROP, ALTER ON `{{app-env-id}}`.* TO `{{app-env-id}}`@`%`
```

**The database of the environment is full.** It reached the storage of its MySQL plan, and [autoscaling](/1.platform/12.billing/11.autoscaling.md) is off. Logs, sessions and caches in tables often grow without anyone noticing. Options:

- Scale the MySQL plan, or turn on autoscaling
- Query large tables, see [below](#query-large-tables)
- Reduce the database size by removing table rows

```mysql
-- Delete table rows with conditions
DELETE FROM table_name WHERE condition;

-- Remove all rows from a table
TRUNCATE TABLE table_name;

-- Drop a table entirely
DROP TABLE table_name;
```

See our [MySQL scaling section](/1.platform/09.components/02.mysql.md#scaling) for some more details.

### Query large tables

This query lists the tables by size, largest first:

```mysql
SELECT
  TABLE_NAME AS `Table`,
  ROUND((DATA_LENGTH + INDEX_LENGTH) / 1024 / 1024) AS `Size (MB)`
FROM
  information_schema.TABLES
WHERE
  TABLE_SCHEMA = '{{app-env-id}}'
ORDER BY
  (DATA_LENGTH + INDEX_LENGTH)
DESC;
```

## max_user_connections error

The app or a client opened more connections at once than allowed:

```sql
SQLSTATE[HY000] [1226] User 'xxxxxx' has exceeded the 'max_user_connections' resource (current value: 10)
```

The limit depends on the plan of the [MySQL component](/1.platform/09.components/02.mysql.md). Typical causes:

- Many PHP requests at the same time
- Each request opens more than one connection
- A cron or worker keeps connections open
- Slow queries hold their connection
- A database GUI opens many connections, see below

Find what keeps connections open and remove the cause, or scale the MySQL plan.

### GUI clients eating MySQL connections

Some GUIs, such as Navicat, Workbench or Sequel Ace, open a connection per tab or query window. Each one counts against the limit of the app. Close tabs, or limit the connections in the client settings. Each connection also opens an SSH tunnel, which counts against the [SSH rate limits](/1.platform/05.code-access/11.ssh-rate-limits.md).

## Access denied; missing SUPER privileges

Importing a dump from a recent `mysqldump` can fail with:

```raw
#1227 - Access denied; you need (at least one of) the SUPER privilege(s) for this operation
```

The dump contains GTID statements, or functions, procedures and triggers with a `DEFINER`, which need the SUPER privilege. Create the dump again with `--set-gtid-purged=OFF`, and with `--no-tablespaces` when it complains about tablespaces. GUIs that run `mysqldump` have a checkbox for GTID. This applies to MariaDB dumps too.

## Large imports

A large import can break off when the tunnel drops. Split the dump into smaller files, or upload it by [SFTP](/1.platform/05.code-access/04.sftp.md) and import it in an SSH session with `mysql`. For the export, `--single-transaction` gives a consistent snapshot without locking the tables.

## Encoding issues

- Add `--default-character-set=utf8mb4` to both export and import commands
- Ensure your dump file is saved with UTF-8 encoding
