## About cloud domains

Every environment has a [default domain](/1.platform/13.domains/01.default-domain.md) built from its ID. A cloud domain adds a name people can remember and type, like `my-shop.frbit.cloud`. It is optional. fortrabbit handles the DNS, so the cloud domain works once it is created. It is served over HTTPS with a free TLS certificate.

## Use cases

- Side projects that don't need a registered domain
- Weekend hacks to share with a link someone can type
- Client hand-over before go-live: the client reviews under the cloud domain, then the cloud domain moves to the environment the client signed off

## Cloud domain and default domain

The default domain is tied to the environment ID and never changes. The cloud domain carries a picked name and can move between environments.

|                             | Default domain | Cloud domain |
| --------------------------- | -------------- | ------------ |
| Name                        | Environment ID | Picked       |
| Created                     | Automatically  | Optional     |
| Move to another environment | No             | Yes          |
| Delete                      | No             | Yes          |
| Per environment             | One            | One at most  |

## Picking a name

Add a cloud domain when creating an app or an environment, or later in the dashboard under domains. App creation suggests a name from the app name, like `my-shop`. Environment creation appends the environment name, like `my-shop-staging`.

- Lowercase letters, digits, and hyphens, up to 63 characters
- No hyphen at the start or the end
- One label only: `my-shop.frbit.cloud` works, `staging.my-shop.frbit.cloud` does not

Names are unique across fortrabbit, first come, first served. Some names are reserved: platform names like `admin`, `login`, `mail`, or `www`, and names that invite phishing, like `bank` or `secure`.

## Moving to another environment

A cloud domain can move to another environment in any app and any region, given developer access to it. The address stays the same. No DNS change is needed. An environment holds one cloud domain at most, so environments that have one cannot be picked. To swap two cloud domains, delete one first, move the other, then create the first again.

## Limits

- The name cannot be changed. Delete the cloud domain and create a new one.
- A deleted name is free again. Someone else can pick it, so don't delete a name a client still uses.
- Deleting an environment deletes its cloud domain. Move the cloud domain first to keep it.
- For a customer-facing production address, add an [external domain](/1.platform/13.domains/03.external-domains.md).
