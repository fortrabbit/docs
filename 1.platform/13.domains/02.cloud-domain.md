## About cloud domains

Every environment has a [default domain](/1.platform/13.domains/01.default-domain.md) built from its ID. A cloud domain adds a readable name like `my-shop.frbit.cloud`. It is optional. fortrabbit handles the DNS, so the cloud domain works once it is created. It is served over HTTPS with a free TLS certificate.

- Show a client the development version under a name they can remember.
- Switch a staging address to a new environment without sending anyone a new URL.
- Run a pet project without registering a domain.

## Cloud domain and default domain

The default domain is tied to the environment ID and never changes. The cloud domain is a name you pick, and it can move between environments.

|                             | Default domain | Cloud domain |
| --------------------------- | -------------- | ------------ |
| Name                        | Environment ID | Picked       |
| Created                     | Automatically  | Optional     |
| Move to another environment | No             | Yes          |
| Delete                      | No             | Yes          |
| Per environment             | One            | One at most  |

## Picking a name

Add a cloud domain when creating an app or an environment, or later in the dashboard under domains. App creation suggests a name from the app name, environment creation from the app and environment names.

- Lowercase letters, digits, and hyphens, up to 63 characters
- No hyphen at the start or the end
- One label only: `my-shop.frbit.cloud` works, `staging.my-shop.frbit.cloud` does not

Names are unique across fortrabbit, first come, first served. Some names are reserved: platform names like `admin`, `login`, `mail`, or `www`, and names that invite phishing, like `bank` or `secure`.

## Moving to another environment

A cloud domain can move to any environment with developer access, in any app and any region. The address stays the same, no DNS change is needed. An environment holds one cloud domain at most, so environments that have one can not be picked. To swap two cloud domains, delete one first, move the other, then create the first again.

## Limits

- **The name can not be changed.** Delete the cloud domain and create a new one.
- **A deleted name is free again.** Someone else can pick it, so don't delete a name a client still uses.
- **Deleting an environment deletes its cloud domain.** Move the cloud domain first to keep it.
- For a customer-facing production address, add an [external domain](/1.platform/13.domains/03.external-domains.md).
