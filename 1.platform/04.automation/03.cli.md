The CLI is a single binary named `frbit` and runs on most operating systems. It is a client of the [public API](/1.platform/04.automation/05.api.md) and it authenticates with a browser sign-in or a personal API token.

- [github.com/fortrabbit/frbit-cli](https://github.com/fortrabbit/frbit-cli)

## Use cases

- A person works from a terminal
- A script runs unattended
- A CI pipeline
- Sets up MCP server and the skills: `frbit setup agent`

See [agent setup](/1.platform/04.automation/01.agents.md) for which tool to use when.

## Scope

- Deploying, restarting and reading deployment logs from a terminal or a CI job
- Reading and setting environment variables without opening the dashboard
- Listing apps, environments, domains and teams, with `--json` for scripts
- Creating an app or a staging environment from a set of component plans
- Wiring the MCP server and the agent skills into a coding agent

The source code, the release archives and the full command reference are in the GitHub repository.

## Install

The install script is the shortest path on macOS and Linux. On a Mac with Homebrew, `brew install fortrabbit/tap/frbit` is the better choice, because `brew upgrade` keeps it current. npm suits machines that already manage tooling that way. The release archives cover everything else, Windows included.

### Install script

```shell
curl -fsSL https://github.com/fortrabbit/frbit-cli/releases/latest/download/install.sh | sh
```

It detects operating system and CPU architecture, downloads the matching GitHub release, verifies its SHA-256 checksum and installs `frbit` in `~/.local/bin`. When run as root, it uses `/usr/local/bin` instead. The script prints a reminder when the install directory is not on `PATH`.

Install a specific release or choose another destination by passing an environment variable to `sh`:

```shell
curl -fsSL https://github.com/fortrabbit/frbit-cli/releases/latest/download/install.sh | FRBIT_VERSION=1.0.0 sh
curl -fsSL https://github.com/fortrabbit/frbit-cli/releases/latest/download/install.sh | FRBIT_INSTALL_DIR="$HOME/bin" sh
```

### Homebrew

The fortrabbit tap provides a binary formula for macOS and Linux:

```shell
brew install fortrabbit/tap/frbit
```

Upgrade an existing installation with `brew upgrade frbit`. Homebrew verifies the SHA-256 checksum generated for each release.

### npm

The npm package installs the native binary for the current platform as an optional dependency:

```shell
npm install --global @fortrabbit/cli
```

Do not install with `--omit=optional`; the wrapper needs its platform package.

### GitHub releases

Archives, checksums and software bills of materials are available on the [GitHub releases page](https://github.com/fortrabbit/frbit-cli/releases). The stable asset names work with generic binary installers such as eget, ubi and mise.

| Platform            | Asset                             |
| ------------------- | --------------------------------- |
| macOS Apple silicon | `frbit_macOS_AppleSilicon.tar.gz` |
| macOS Intel         | `frbit_macOS_Intel.tar.gz`        |
| Linux arm64         | `frbit_linux_arm64.tar.gz`        |
| Linux x86-64        | `frbit_linux_amd64.tar.gz`        |
| Windows arm64       | `frbit_windows_arm64.zip`         |
| Windows x86-64      | `frbit_windows_amd64.zip`         |

Confirm the installation with `frbit version`.

### Shell completion

Homebrew installs shell completion. For the other install methods, run the command for the shell once:

```shell
frbit completion install zsh   # or bash, fish, powershell
```

## Authenticate

The CLI signs in once in the browser and keeps the credential in the operating-system credential store. Automated jobs skip that and pass a personal API token per command instead.

```shell
frbit auth login
```

The command prints a URL and a code, and opens the URL in the default browser. Log in, or sign up when there is no account yet, then type the code and approve `frbit CLI`. The code shows that the sign-in in the browser belongs to this terminal. The CLI waits up to 15 minutes for that. `--no-browser` only prints the URL, for a machine without a browser. `--json` prints the URL, the code and the result as JSON lines, for coding agents.

The credential expires after an hour and renews itself. It shows up under `AI agents` in the account menu of the dashboard, where it can be disconnected. `frbit auth status` shows the stored credential and the next open setup step, `frbit auth logout` removes it again.

### Tokens in scripts and CI

Create a personal API token under `API tokens` in the account menu of the dashboard. `FRBIT_TOKEN` supplies it for a single process and takes precedence over a stored credential, which makes it the right fit for CI jobs and containers. `frbit auth login` refuses to run while it is set:

```shell
FRBIT_TOKEN=frbit-at-… frbit apps list
```

To store a token without an interactive prompt, pass it on standard input. Avoid putting tokens into shell history, command arguments or source control:

```shell
printf '%s' "$FRBIT_TOKEN" | frbit auth login --token-stdin
```

### Profiles

Separate accounts are kept apart by profile. The default profile is named `default`, and `--profile` goes before the command group:

```shell
frbit --profile work auth login
frbit --profile work apps list
```

## Commands

Commands are grouped by resource and mirror the API. Reads accept `--page` and repeatable `--id`, and `--json` prints the API response unchanged for use with `jq`.

| Group                      | Covers                                                        |
| -------------------------- | ------------------------------------------------------------- |
| `auth`                     | login, status, logout                                         |
| `apps`                     | list, get, create, update, delete                             |
| `environments`             | list, get, create, update, delete, variables, restart, deploy |
| `deployments`              | list, get, logs                                               |
| `domains`                  | list, get, delete                                             |
| `people`                   | list, get                                                     |
| `teams`, `payment-methods` | list, get, delete                                             |
| `setup`, `mcp`, `skills`   | agent integration                                             |

A few everyday examples:

```shell
frbit apps list
frbit environments variables get en-a1b2c3
frbit environments deploy en-a1b2c3
frbit deployments logs dp-a1b2c3
```

Every command and option of the installed version is available under `--help`, for example `frbit apps list --help`. The [complete command reference](https://github.com/fortrabbit/frbit-cli/blob/main/docs/cli.md) is maintained next to the source code.

API responses can contain account data, environment-variable values and application log output. Treat terminal captures and CI logs as sensitive, especially around `--json` and `deployments logs`.

### Delete resources

Apps, environments, domains, teams and payment methods can be deleted. The CLI shows what will be lost and asks for the exact public ID before it deletes. In scripts, repeat the ID with `--confirm`:

```shell
frbit apps delete ap-a1b2c3 --confirm ap-a1b2c3
```

Deleting an app or environment erases its files and database for good. Deleting a team or payment method can also delete the apps connected to it.

## MCP server setup

The CLI also wires fortrabbit into a coding agent, so the [MCP server](/1.platform/04.automation/02.mcp.md) and the [agent skills](/1.platform/04.automation/04.agent-skills.md) do not have to be registered by hand:

```shell
frbit setup agent
```

It detects Claude Code and Codex, registers the MCP server with each and installs the latest skills. Repeating `--agent claude-code` or `--agent codex` bypasses detection. The `frbit mcp` and `frbit skills` command groups manage either side on its own.

## Updates

`frbit version` reports the installed release, its source commit and build date. Interactive sessions check GitHub for a newer stable version at most once per day. The check is silent on network errors and can be turned off:

```shell
export FRBIT_NO_UPDATE_NOTIFIER=1
```

Upgrading follows the install method: re-run the install script, `brew upgrade frbit` or `npm update --global @fortrabbit/cli`.

## Uninstall

Undo the agent setup and sign out while the binary is still in place:

```shell
frbit mcp remove --yes
frbit skills remove --yes
frbit auth logout
```

`--yes` skips the confirmation, which an agent can't answer. `frbit auth logout` removes the stored credential for the selected profile — repeat it with `--profile` for every profile in use. It does not end the sign-in on the account side: disconnect `frbit CLI` under `AI agents` in the account menu of the dashboard.

Then remove the binary with the counterpart of the install method:

```shell
# install script or release archive
rm "$(command -v frbit)"

# Homebrew
brew uninstall frbit

# npm
npm uninstall --global @fortrabbit/cli
```

`brew untap fortrabbit/tap` is only needed when no other formula from the fortrabbit tap remains. Generic binary installers clean up after themselves, for example `eget --remove` or `mise uninstall`.

Small files stay behind: the saved API host and a lock file in the config folder, the last update check in the cache folder. Tokens are not in them: `frbit auth logout` removes those from the credential store of the operating system. Delete both folders for a clean slate:

| System  | Config folder                         | Cache folder               |
| ------- | ------------------------------------- | -------------------------- |
| macOS   | `~/Library/Application Support/frbit` | `~/Library/Caches/frbit`   |
| Linux   | `~/.config/frbit`                     | `~/.cache/frbit`           |
| Windows | `%AppData%\frbit`                     | `%LocalAppData%\frbit`     |
