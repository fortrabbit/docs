| Tool                                                         | What it is                    | Authentication       | Use case                  |
| ------------------------------------------------------------ | ----------------------------- | -------------------- | ------------------------- |
| [MCP server](/1.platform/04.automation/02.mcp.md)            | Remote endpoint for AI agents | Browser sign-in      | Personal AI agent         |
| [CLI](/1.platform/04.automation/03.cli.md)                   | `frbit` binary, client of API | Browser or API token | AI agent, script, CI jobs |
| [Agent skills](/1.platform/04.automation/04.agent-skills.md) | Workflow instructions         | Nothing of their own | Help your agent succeed   |
| [Public API](/1.platform/04.automation/05.api.md)            | REST interface over HTTP      | Personal API token   | Build an integration      |

## How they relate

```raw
  platform
  │
  ├── MCP server   ◀── browser sign-in ──  AI agent
  │
  └── public API   ◀── API token ────────  own code, integrations
      │
      └── CLI      ◀── browser sign-in ──  terminal, AI agent
                   ◀── API token ────────  CI job, script
```

The public API is the base layer and the CLI is a client of it. On a person's computer the CLI signs in through the browser; in a CI job it takes a personal API token, like the API. The MCP server is a second front door with its own sign-in, not a wrapper around the REST API.

Agent skills sit outside that picture. They hold no credentials and open no connection. They tell an agent how a deployment works on fortrabbit, how a database is synced, and which command to run over SSH. The agent acts through the connection it has.

The common pair is the MCP server plus agent skills: the agent sees the account and follows the platform workflows. `frbit setup agent` installs both in one command.

## Browser sign-in or API token

A person at their own computer signs in through the browser: `frbit auth login` for the CLI, the client's own login for MCP. Anything that runs without a person present, such as a CI job, a server or an integration, takes a personal API token.

|           | Browser sign-in                | API token           |
| --------- | ------------------------------ | ------------------- |
| Created   | `frbit auth login`, MCP client | Dashboard           |
| Expires   | After 30 days unused           | Never               |
| Access    | Fixed per client               | Chosen at creation  |
| Revoke at | `Connections`                  | `API tokens`        |

An MCP client without OAuth support takes a personal API token as a bearer credential instead of the browser sign-in.
