## About credentials

A browser sign-in starts in the MCP client or with `frbit auth login`. A person approves it in the dashboard, and the tool stores and renews it. An API token is created in the dashboard and pasted where needed.

A browser sign-in works only for the tool that started it. An API token works for the CLI and the public API, not for the MCP server.

## Where each credential works

| Credential   | MCP server | CLI and public API |
| ------------ | ---------- | ------------------ |
| MCP sign-in  | Yes        | No                 |
| CLI sign-in  | No         | Yes                |
| API token    | No         | Yes                |

Agent skills hold no credential of their own. They use the MCP server or the CLI.

## What each credential may do

| Credential                         | Read | Write | Delete       |
| ---------------------------------- | ---- | ----- | ------------ |
| MCP sign-in                        | Yes  | Yes   | Not offered  |
| CLI sign-in                        | Yes  | Yes   | When allowed |
| API token, read                    | Yes  | No    | No           |
| API token, read and write          | Yes  | Yes   | No           |
| API token, read, write and delete  | Yes  | Yes   | Yes          |

Write means create and change. Over MCP, an agent creates apps and environments, changes environment variables, deploys and restarts. No MCP tool deletes.

The CLI sign-in deletes only when `Allow deletes` was ticked on approval. Restoring a backup and switching a component off count as deletes, see [token permissions](/1.platform/04.automation/05.api.md#token-permissions).

## Lifetime and revocation

|         | Browser sign-in                                | API token     |
| ------- | ---------------------------------------------- | ------------- |
| Created | MCP client, `frbit auth login`                 | Dashboard     |
| Expires | 1 year after approval, or after 30 days unused | Never         |
| Revoke  | `Connected apps` in the account menu           | `API tokens`  |

The dashboard lists each browser sign-in under `Connected apps`, with its access, last use and end date. `Remove` there disconnects every app at once, for a lost laptop or a leaked token. An app removed by mistake signs in again on its next use.

## Which one to use

- A person at their own computer: the browser sign-in.
- A CI job, a script or a server: an API token with the smallest permission that covers the job.
