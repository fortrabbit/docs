The skill works with [Claude Code](/4.integrations/17.ai-coding/02.claude-code.md), [OpenAI Codex](/4.integrations/17.ai-coding/04.codex.md) and [GitHub Copilot](/4.integrations/17.ai-coding/03.github-copilot.md), and with other agents that read the open Agent Skills format.

- [github.com/fortrabbit/agent-skills](https://github.com/fortrabbit/agent-skills) - source code

The skill is recommended but not required. An agent can work with fortrabbit through the [CLI](/1.platform/04.automation/03.cli.md) or the [MCP server](/1.platform/04.automation/02.mcp.md) alone. The skill tells it which of the two to use for a task, and covers what neither does: SSH, database and file sync.

## Use cases

- An agent should deploy, sync a database, or run remote commands
- The agent keeps guessing at platform conventions
- A project should go from a local folder to a live app in one session

## Install

### With the frbit CLI

The [frbit CLI](/1.platform/04.automation/03.cli.md) installs the skill and connects the MCP server in one step:

```shell
frbit setup agent
```

For the skill alone:

```shell
frbit skills install                    # user scope, for the agents found on this machine
frbit skills install --project          # into the current project, for all three agents
frbit skills install --agent copilot    # one agent: claude-code, codex or copilot
```

### With the GitHub CLI or npx

Requires [GitHub CLI](https://cli.github.com/) v2.90.0 or later:

```shell
gh skill install fortrabbit/agent-skills fortrabbit --agent claude-code --scope user
npx skills add fortrabbit/agent-skills
```

### As a Claude Code plugin

The plugin bundles the skill and the MCP server. In Claude Code:

```shell
/plugin marketplace add fortrabbit/agent-skills
/plugin install fortrabbit@fortrabbit
```

Then run `/mcp`, pick the fortrabbit server and log in.

Use the plugin or one of the other installs for Claude Code, not both: each adds its own copy of the skill and the MCP server. To switch to the plugin, remove the other copies first:

```shell
frbit skills remove --agent claude-code --yes
claude mcp remove fortrabbit
```

## Use the skill

There are no commands to learn. Ask the agent in plain words: "deploy this", "pull the production database", "why does the site return a 500?". The skill loads when a request is about fortrabbit, a `frbit.app` hostname or an environment ID. In Claude Code, `/fortrabbit` loads it on purpose, `/fortrabbit:fortrabbit` from the plugin.

The agent finds the environment from the git remote and the current branch. It shows a command before anything that changes a live environment and waits for a yes.

## Update

Each install method updates the skill its own way:

```shell
# frbit CLI, with --project or --agent as at install
frbit skills update

# GitHub CLI
gh skill update fortrabbit

# npx
npx skills update fortrabbit

# Claude Code plugin, MCP server included
claude plugin update fortrabbit@fortrabbit
```

Removing the skill, per install method: [remove the agent setup](/1.platform/04.automation/06.uninstall.md#agent-skills).

## Upgrade from version 1

Version 2 merges the `fortrabbit-api-access` skill into `fortrabbit`, drops the commands such as `/fortrabbit db up`, and drops the curl installer and the `.fortrabbit` project file. `frbit skills update` with CLI 1.7.0 or later removes the old files. After a `gh skill` install, delete them yourself:

```shell
rm -rf ~/.claude/skills/fortrabbit-api-access ~/.agents/skills/fortrabbit-api-access
```

## Connect the MCP server

The skill works over SSH without the [MCP server](/1.platform/04.automation/02.mcp.md). Connected, the agent also lists and creates apps and environments, changes environment variables and reads deployment logs. Asked to connect, the skill walks through the setup.

## Scripts and CI

Without a browser, a [public API token](/1.platform/04.automation/05.api.md) takes the place of the login. The skill reads it from `FORTRABBIT_API_TOKEN` and never writes it to a committed file.

## Requirements

- `git` and `ssh` available locally, port 22 open
- `rsync` for file sync, a MySQL client for database work
- On Windows, WSL is required for rsync; SSH works natively on Windows 10+
