## Sign in

frbit signs in once in the browser and keeps the credential in the credential store of the operating system. CI jobs use a [personal API token](#tokens-in-scripts-and-ci) instead.

```shell
frbit auth login
```

The command prints a URL and a code, and opens the URL in the default browser. Log in, or sign up when there is no account yet, then type the code and approve `frbit CLI`. The code ties the sign-in in the browser to this terminal. frbit waits up to 15 minutes; when the last browser login is older than 2 hours, the dashboard asks to log in again first.

`--no-browser` only prints the URL, for a machine without a browser. `--json` prints the URL, the code and the result as JSON lines, for coding agents.

The approval page offers `All apps`, preselected, or `Chosen apps`. With chosen apps, frbit reaches the checked apps and the apps it creates; every other app answers like an unknown ID. To change the list, run `frbit auth login` again.

The approval page also has an `Allow deletes` box, unticked by default. Without it, the CLI can read and change everything, but deletes, backup restores and switching a component off fail and ask to run `frbit auth login` again, this time with the box ticked. A new `frbit auth login` ends the earlier frbit CLI login of the account, also on other machines.

The credential expires after an hour and renews itself. The connection ends one year after approval, or after 30 days without use, whichever comes first; then run `frbit auth login` again. It is listed under [OAuth tokens](https://dash.fortrabbit.com/credentials/oauth-tokens) in the dashboard. Its page there lists the apps and deletes the OAuth token.

An expired or revoked sign-in fails with `the sign-in expired or was revoked` and the `frbit auth login` command for the profile and host in use. A refused `FRBIT_TOKEN` is named as such.

After the sign-in, frbit prints the next setup step. While the account has no SSH key, it prints `Add an SSH key` with `frbit ssh-keys add`: `frbit ssh`, `frbit db` and `frbit files` need one.

`frbit auth status` shows the stored credential and the next open setup step. `frbit auth logout` removes it.

### Tokens in scripts and CI

Create a personal API token under [API tokens](https://dash.fortrabbit.com/credentials/api-tokens) in the dashboard, limited to the apps the job needs. `FRBIT_TOKEN` passes it to a single process and wins over a stored credential, which suits CI jobs and containers. `frbit auth login` refuses to run while it is set:

```shell
FRBIT_TOKEN=frbit-at-… frbit apps list
```

To store a token without an interactive prompt, pass it on standard input. Avoid putting tokens into shell history, command arguments or source control:

```shell
printf '%s' "$FRBIT_TOKEN" | frbit auth login --token-stdin
```

### Profiles

Separate accounts are kept apart by profile. The default profile is named `default`, and `--profile` goes before the command group:

```shell
frbit --profile work auth login
frbit --profile work apps list
```

## Link the project

Run it in the project folder:

```shell
frbit link                              # show the environment of this folder
frbit link en-a1b2c3                    # link it, under the name of the current branch
frbit link en-d4e5f6 --label staging
frbit link shop/production
```

With a GitHub repository connected to the app, `frbit link` finds the environment that deploys the current branch and writes nothing. Otherwise it writes `.fortrabbit/environments.yml` at the top of the git checkout, a map of label to environment ID. Commit the file. From then on, `frbit ssh`, `frbit db pull` and most other commands work without an environment ID.

## Connect a coding agent

```shell
frbit setup agent
```

It detects Claude Code and Codex, registers the [MCP server](/1.platform/04.automation/02.mcp.md) with each and installs the latest [agent skills](/1.platform/04.automation/04.agent-skills.md). `--agent claude-code` or `--agent codex`, repeatable, skips the detection. `--remove` undoes the setup and signs the CLI out. Other agents connect as described in [agent setup](/1.platform/04.automation/01.agents.md).

## Shell completion

Homebrew sets it up. With the other install methods, run once:

```shell
frbit completion install zsh   # or bash, fish, powershell
```

## Check the setup

```shell
frbit doctor
```

It checks the CLI version against the latest release, the sign-in, `ssh`, `rsync` and `git`, the linked environment with an SSH connection, and the agent setup. Each problem comes with the fix, a missing SSH key on the account or on this machine included. It exits with 1 when a check fails, and `--json` prints the result for agents.
