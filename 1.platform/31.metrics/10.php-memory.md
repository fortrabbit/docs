## About PHP memory

Every five minutes the highest memory use of all PHP processes is recorded, including the memory they share for OPcache and extensions. Each bar shows the lowest value, the mean measure, and the highest value of its hour or day. The mean measure is the 99th percentile by default; switch it to the median or the average in the options. Horizontal lines mark the PHP plan sizes.

:BlockLink{title="See PHP memory for {{app-env-name}}" path="/environments/{{app-env-id}}/metrics/php-memory"}

## What to look for

Memory follows the number of busy PHP processes and what each request loads. Peaks close to the plan limit are a warning. At the limit, a process is killed and counted under [OOM kills](/1.platform/31.metrics/12.php-oom-kills.md). High memory with few [PHP requests](/1.platform/31.metrics/09.php-requests.md) points to code that loads too much at once: large result sets, images processed in memory, or a leak in a long request.

## What to do

Find the requests that run when memory peaks, in the [logs](/1.platform/07.settings/25.logs.md) or an [APM tool](/4.integrations/04.apm/01.intro.md), and reduce what they load. [PHP processes](/3.dev/02.performance/06.php-processes.md) explains how processes share memory. Scale the [PHP component](/1.platform/09.components/01.php.md#scaling) when the usage is legitimate.
