## About jobs memory

Every 5 minutes the highest memory use of the jobs container is recorded, all [workers](/1.platform/30.jobs/03.workers.md) and [crons](/1.platform/30.jobs/02.crons.md) together. Each bar shows the lowest value, the 99th percentile and the highest value of its hour or day. Horizontal lines mark jobs plan sizes.

:BlockLink{title="See Jobs memory for {{app-env-name}}" path="/environments/{{app-env-id}}/metrics/jobs-memory"}

## What to look for

Workers are long-running PHP processes. Memory that climbs steadily and drops only on a restart points to a leak: each processed job leaves something behind. Short peaks line up with cron schedules or large jobs. Once the plan limit is reached, a process is killed and shows up under [jobs OOM kills](/1.platform/31.metrics/12.jobs-oom-kills.md).

## What to do

Let workers restart after a number of jobs or a memory limit, most queue libraries have an option for it. Split large jobs into smaller batches. [Tune jobs](/1.platform/30.jobs/05.tuning.md) covers both. Scale the [Jobs component](/1.platform/09.components/07.jobs.md#scaling) when the usage is legitimate.
