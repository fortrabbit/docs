## About PHP memory

Every 5 minutes the highest memory use of the PHP container is recorded. It covers all PHP processes plus the shared memory of OPcache and extensions. Each bar shows the lowest value, the 99th percentile and the highest value of its hour or day. Horizontal lines mark PHP plan sizes.

:BlockLink{title="See PHP memory for {{app-env-name}}" path="/environments/{{app-env-id}}/metrics/php-memory"}

## What to look for

Memory follows the number of busy PHP processes and what each request loads. Peaks close to the plan limit are a warning. Once the limit is reached, a process is killed and shows up under [OOM kills](/1.platform/31.metrics/10.php-oom-kills.md). High memory with few [PHP requests](/1.platform/31.metrics/07.php-requests.md) points to code that loads too much at once: large result sets, big images processed in memory, or a leak in a long request.

## What to do

Look at the requests that run when memory peaks, in the [logs](/1.platform/07.settings/25.logs.md) or an [APM tool](/4.integrations/04.apm/01.intro.md). Reduce what they load before scaling. [PHP processes](/3.dev/02.performance/06.php-processes.md) explains how processes share memory. Scale the [PHP component](/1.platform/09.components/01.php.md#scaling) when the usage is legitimate.
