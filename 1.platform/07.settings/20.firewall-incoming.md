## About the incoming firewall

Bots scan websites for vulnerabilities and content all day. Even a request that fails takes up a PHP process and adds lines to the logs. AI crawlers that ignore `robots.txt` can send enough requests to slow a website down.

The incoming firewall uses the rules of [nG Firewall](https://perishablepress.com/ng-firewall/) by Perishable Press. Apache checks every request against them and answers a match with a [403 error](/3.dev/22.http-status-codes/others/403.md), without starting PHP.

## Usage

Turn the incoming firewall on and off in the environment settings in the dashboard.

:BlockLink{title="Set WAF for {{app-name}} / {{app-env-name}}" path="/environments/{{app-env-id}}/settings/firewall-incoming"}

## Quirks

- **Apache load**: the rules add work to every request in Apache, while fewer requests reach PHP.
- **Software installers**: the rules can block the installer of a CMS. Install the software first, then turn the firewall on.

## Alternatives

### Own .htaccess rules

Write rules for the specific case in `.htaccess`. To block single IPs or ranges, see [block IPs with .htaccess](/3.dev/21.htaccess/08.block-ip.md), or browse the [.htaccess section](/3.dev/21.htaccess/01.intro.md).

### External service

Some DNS and CDN providers filter bot traffic before it reaches the web server:

- [Cloudflare bot management](https://www.cloudflare.com/application-services/products/bot-management/)
- [AWS WAF Bot Control](https://aws.amazon.com/waf/features/bot-control/)
