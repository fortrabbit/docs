## About metrics

Metrics are measured on the platform, outside the app. No code, agent, or extension is needed. Values are sampled every five minutes and grouped into bars.

:BlockLink{title="See metrics for {{app-name}} / {{app-env-name}}" path="/environments/{{app-env-id}}/metrics"}

## Time frame and resolution

The time frame sets the range and what one bar stands for. Times are UTC.

| Time frame           | One bar |
| -------------------- | ------- |
| Last two days        | Hour    |
| Last 30, 60, 90 days | Day     |
| Previous two months  | Day     |

## Reading the charts

Counts, such as requests, traffic, errors, and OOM kills, show one bar per hour or day that holds its total.

Web storage and MySQL storage show four values per bar: the highest size, the size at the end of the hour or day, the average, and the lowest size. The highest size explains a larger plan booked that day. The size at the end shows whether a cleanup worked.

PHP memory and jobs memory show the highest peak and the typical peak, the median. Every five minutes, the platform keeps the memory peak of those five minutes. The highest peak is the value to compare with the memory of the plan. A typical peak far below it points to rare spikes. PHP OPcache shows the highest fill of each hour or day.

PHP response time shows the slowest and the fastest request, plus one measure picked in the options: the 99th percentile, the median, or the average. The 99th percentile is the default, the value 99% of requests stay below. It ignores rare outliers, but still shows slow requests that happen regularly. The fastest request reads as an upper bound, such as "≤ 5 ms": the platform counts requests per duration range, not each duration.

Horizontal lines mark plan sizes or thresholds. The figures next to the chart summarize the whole time frame. Request and error metrics add a table that names the URLs behind the numbers.

## Metrics, logs, and APM

Metrics show that something changed, and when. [Logs](/1.platform/07.settings/25.logs.md) show the single request behind it. An [APM tool](/4.integrations/04.apm/01.intro.md) traces a request through the code. Start with the metric, narrow the time frame, then read the logs for that window.
