## About the root path

A request for `https://example.com/about` ends up in the root path: the web server looks there for a file named `about`, or hands the request to the `index.php` in it. Everything above the root path stays private, such as configuration files, the `vendor` folder and `.env`. A wrong root path shows as [404 errors](/3.dev/22.http-status-codes/404.md) on every page.

## Plain PHP projects

In a traditional PHP project, the root path is the top level of the code, holding `index.php`:

```raw
www <-- Root path
├── index.php  <-- file to be called
├── css/
├── js/
├── images/
├── includes/
```

All files are reachable by URL here, including the scripts in `includes/`.

## Frameworks and CMS

Most frameworks keep the code outside the root path and serve only one folder:

```raw
www
├── public/ <-- Root path
│   └── index.php <-- file to be called
├── src/
├── vendor/
└── composer.json
```

The `src/` and `vendor/` folders are out of reach of the web. Common root paths:

- `public`: Laravel, Statamic, Symfony, TYPO3
- `web`: Craft CMS, Drupal
- the top level: Kirby, Grav, October CMS

## Root path setting on fortrabbit

The code of an environment sits in `/data/www`, see [directories](/1.platform/05.code-access/05.directories.md). The root path setting names the folder inside it, such as `public` for `/data/www/public`, without the index file. The [software template](/1.platform/03.concepts/05.software-templates.md) fills in the root path the software expects, and it can be changed in the environment settings at any time.

All [domains](/1.platform/10.objects/10.domain.md) of an environment share the root path. To serve different folders per domain, use [rewrite rules in .htaccess](/3.dev/21.htaccess/02.redirects.md).
