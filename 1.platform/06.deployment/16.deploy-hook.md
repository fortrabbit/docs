Deploy hooks are unique URLs that accept HTTP POST requests to trigger a [deployment](/1.platform/10.objects/11.deployment.md) on an [environment](/1.platform/10.objects/02.environment.md).

## Settings

Deploy hooks are configured in the fortrabbit dashboard for each environment.

:BlockLink{title="Deploy hook settings for {{app-name}} / {{app-env-name}}" path="/environments/{{app-env-id}}/deployment#deploy-hook"}

Enabling the deploy hook shows its URL. Store it like a password.

## Trigger

Send a POST request to the URL. No authentication and no payload are needed:

```bash
# Trigger
curl -X POST "https://api.fortrabbit.com/webhooks/environments/{{app-env-id}}/deploy/{{SECRET}}" \
  -H "User-Agent: fortrabbit"
```

A started deployment answers with status `202` and the ID of the [deployment](/1.platform/10.objects/11.deployment.md):

```json
{
  "data": {
    "publicId": "dp-abc123"
  }
}
```

A wrong URL, a revoked secret or a disabled deploy hook all answer with status `404`:

```json
{
  "error": "Not found"
}
```

## Use cases

- Deploy when a headless CMS such as Contentful or Strapi publishes
- Deploy on a schedule, from a cron job or a workflow tool
- Deploy from a CI pipeline after the tests passed

## Example

A GitHub Actions step that triggers a deployment, with the URL stored as a secret:

```yaml
deploy:
  runs-on: ubuntu-latest
  steps:
    - name: Trigger fortrabbit deploy
      run: |
        curl -X POST "${{ secrets.FORTRABBIT_DEPLOY_HOOK_URL }}" \
          -H "User-Agent: fortrabbit"
```

The hook deploys the latest commit of the connected branch, not the commit the workflow ran on. See [GitHub](/4.integrations/03.git-providers/02.github.md) for more on GitHub Actions.

For day-to-day work, [push to deploy](/1.platform/06.deployment/05.trigger.md) with the [GitHub App](/1.platform/06.deployment/02.github-app.md) needs no hook.

## Security

Anyone with the URL can deploy the environment. The hook ignores the [deployment permission](/1.platform/06.deployment/18.permission.md) and the deployment trigger. Treat the URL like a password or API token. When it leaks, revoke it in the dashboard and create a new one.

## Troubleshooting

When a deploy hook does not deploy:

- **404 response**: the URL is wrong, revoked, or the hook is disabled. Copy the URL again from the dashboard.
- **No response**: the calling service cannot reach `api.fortrabbit.com`.
- **202 response**: the deployment started. Its result shows in the deployment history of the environment.
