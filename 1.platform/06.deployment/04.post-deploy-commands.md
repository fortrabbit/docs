## About post deploy commands

[Build commands](/1.platform/06.deployment/03.build-commands.md) prepare the code before it goes live. Post deploy commands run after the code is copied into the environment, in the deployment container. They run in order, one after the other.

Typical tasks:

- Database migrations
- Clearing or warming caches
- Applying project config, such as in Craft CMS
- Rebuilding a search index

## Software template commands

The [software templates](/1.platform/03.concepts/05.software-templates.md) set post deploy commands for Laravel, Symfony, Craft CMS and others, such as `php artisan migrate --force` for Laravel. The software templates page lists the commands of every template.

## Failed post deploy commands

When a post deploy command fails, the [deployment](/1.platform/10.objects/11.deployment.md) shows as failed, while the new code is already live. The [deploy log](/1.platform/06.deployment/17.logs.md) shows which command failed. Fix the command or the code, and deploy again.

## Best practices

- **Idempotent commands**: a command can run again on the next deployment without harm, as migrations do.
- **Caches**: clearing all caches on every deployment makes the first requests slow while they rebuild. Clear what the new code needs.
- **Short commands**: long tasks, such as a full import, belong in a [job](/1.platform/30.jobs/01.usage.md).
