Exclude patterns work with both [deployment strategies](/1.platform/06.deployment/08.strategy.md). An excluded file or folder is not copied from the deploy package, and what exists under that path on the web storage stays as it is. With the merge strategy this keeps build leftovers like `node_modules` out of the web storage. With the replace strategy, which deletes everything else first, it is also what preserves user uploads, assets, and other runtime data across deployments. Generally, exclude runtime data: files and folders created by the application, not tracked in Git. This typically includes user uploads, logs, and sessions.

::CallOut
When the repository contains a [deploy file](/1.platform/06.deployment/06.deploy-file.md), this setting is managed there and cannot be edited in the dashboard.
::

Sensible defaults based on [software templates](/1.platform/03.concepts/05.software-templates.md) are provided.

Rsync syntax is supported, allowing regex like patterns. The asterisk `*` serves as a wildcard. Patterns are matched starting from the [Git source directory](/1.platform/06.deployment/09.git-source-directory.md).

## Examples

```yml
## WordPress
/wp-content

## Laravel
/storage

## Kirby CMS (if using git + rsync)
/content
/media

## Wildcard (rsync regex) syntax
*/files

## Exclude files from the final build
/node_modules
```

## One setting, two use cases

- **Exclude from deployment**: Prevent files from being copied to the environment. Works with both strategies.
  - Useful for files that are only needed during the build.
  - `node_modules` is the common case, and the software templates set it.
- **Preserve on environment**: Prevent files from being deleted by the replace strategy.
  - Essential for runtime data created by the application.
  - Example: User uploads, content files, and logs.

## Related

With the merge strategy, [replace patterns](/1.platform/06.deployment/15.replace-patterns.md) do the reverse: they name folders that are swapped completely while everything else is kept.
