The code from Git and the results of the build commands form the deploy package. The strategy decides how it goes into the storage of the environment. The [software template](/1.platform/03.concepts/05.software-templates.md) sets it, and the software templates page lists the strategy of each one. Apps without a template start with merge. Change it in the deployment settings.

::CallOut
When the repository contains a [deploy file](/1.platform/06.deployment/06.deploy-file.md), this setting is managed there and cannot be edited in the dashboard.
::

## Merge strategy

Merge overwrites but does not delete:

- Files in the deploy package overwrite their copies in the storage.
- New files are created.
- **Files in the storage that are not in the deploy package stay.**

Uploads, image transforms and cache files survive without further setup. Files deleted in Git stay in the storage, though, and can confuse the software. [Replace patterns](/1.platform/06.deployment/15.replace-patterns.md) name folders to swap completely. [Exclude patterns](/1.platform/06.deployment/10.exclude-patterns.md) keep build leftovers like `node_modules` out of the storage.

## Replace strategy

The storage becomes an exact copy of the deploy package: everything else is deleted. This is sometimes called an immutable deployment, in line with 12-factor apps that write nothing to disk. Every deployment starts from a known state.

[Exclude patterns](/1.platform/06.deployment/10.exclude-patterns.md) name the files and folders that survive, such as user uploads. Without them, uploads are gone after the next deployment.
