::CallOut{alert}
The deploy file is a new feature. The format and behavior described here may still change.
::

The deploy file is a configuration file in your Git repository that describes how an environment is deployed: which commands run during the build, how the build result is distributed to the environment and more. It is an alternative to configuring those settings in the dashboard, with the advantage that deployment settings are versioned, reviewable and shipped together with the code.

When a deploy file is present, it takes over from the dashboard. See [deploy file and dashboard](#deploy-file-and-dashboard) below.

## File location

The deploy file lives in the `.fortrabbit` directory in the root of your repository. It is recognized under one of these names, in this order:

- `.fortrabbit/deploy.yml`
- `.fortrabbit/deploy.yaml`
- `.fortrabbit/deploy.json`

Only the first file that is found is used.

## Format

The deploy file is a YAML mapping. Every file starts with an `apiVersion` and groups the settings into two sections: `build` and `distribution`.

```yml [.fortrabbit/deploy.yml]
apiVersion: 1.0
build:
  buildCommands:
    - composer install --no-dev --prefer-dist --no-interaction
    - npm ci && npm run build
  postDeployCommands:
    - php artisan optimize:clear
  cachedDirectories:
    - bootstrap/cache
distribution:
  gitSourceDirectory: web
  strategy: replace
  excludePatterns:
    - storage
```

The same configuration can also be written as JSON:

```json [.fortrabbit/deploy.json]
{
  "apiVersion": 1.0,
  "build": {
    "buildCommands": [
      "composer install --no-dev --prefer-dist --no-interaction",
      "npm ci && npm run build"
    ],
    "postDeployCommands": [
      "php artisan optimize:clear"
    ],
    "cachedDirectories": [
      "bootstrap/cache"
    ]
  },
  "distribution": {
    "gitSourceDirectory": "web",
    "strategy": "replace",
    "excludePatterns": [
      "storage"
    ]
  }
}
```

## Build

The `build` section contains everything that happens while the deploy package is being produced:

- `buildCommands` — commands executed during the build, like [build commands](/1.platform/06.deployment/03.build-commands.md)
- `postDeployCommands` — commands executed after the deploy package reached the environment, like [post deploy commands](/1.platform/06.deployment/04.post-deploy-commands.md)
- `cachedDirectories` — directories kept between deployments to speed up the build, like [cached directories](/1.platform/06.deployment/07.cached-directories.md)

## Distribution

The `distribution` section describes how the deploy package reaches the web space:

- `gitSourceDirectory` — the subdirectory treated as root, like the [Git source directory](/1.platform/06.deployment/09.git-source-directory.md)
- `strategy` — `merge` or `replace`, like the [deployment strategy](/1.platform/06.deployment/08.strategy.md)
- `excludePatterns` — files and folders to keep during a replace deployment, like [exclude patterns](/1.platform/06.deployment/10.exclude-patterns.md)
- `replacePatterns` — files and folders to delete during a merge deployment, like [replace patterns](/1.platform/06.deployment/15.replace-patterns.md)

`replacePatterns` can only be used together with the `merge` strategy. With `replace` everything is replaced anyway, so there is nothing to delete beforehand.

## Deploy file and dashboard

As soon as a deploy file is found on the deployed branch, it is the only source for the deployment settings it covers:

- **Dashboard settings disabled** — the deployment settings page of the environment shows the values from the file with a link to it. Build commands, post deploy commands, cached directories, Git source directory, deployment strategy, exclude patterns and replace patterns can no longer be edited in the dashboard.
- **File used for deployments** — every deployment reads the deploy file from the commit it deploys. A change to the settings is a commit and a push.
- **No fallback to dashboard values** — settings left out of the file are empty for that deployment. They are not taken from the dashboard. Put every setting the environment needs into the file.
- **Dashboard values kept** — the values saved in the dashboard are not overwritten. They stay stored in the background, unused while the file exists.
- **Other settings stay in the dashboard** — the [deployment trigger](/1.platform/06.deployment/05.trigger.md), the [deploy hook](/1.platform/06.deployment/16.deploy-hook.md), the PHP version and the Node.js version are not part of the deploy file and remain editable in the dashboard.

When creating a new app, the dashboard checks the selected branch for a deploy file. If one is found, the steps for deployment and post deploy commands are skipped.

### Invalid deploy file

A deploy file that cannot be read, for example because of broken YAML or an unsupported field, fails the deployment. The failed deployment in the dashboard shows the error. The dashboard settings are not used as a fallback. Fix the file and push again.

### Removing the file

Delete the deploy file from the repository and push. The next deployment uses the settings saved in the dashboard again, and they become editable there.
