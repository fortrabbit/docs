## Get ready

For a first setup, check the basics:

- New to Git? Read the [Git intro](/3.dev/15.learn/git-intro.md) first
- Read the [deployment intro](/1.platform/06.deployment/01.intro.md)
- Have the [fortrabbit GitHub app](/1.platform/06.deployment/02.github-app.md) installed with GitHub
- Have an environment connected to a repo at GitHub

## GitHub connectivity errors

`git push` shows an error, or the commit does not show up on GitHub. The problem sits between the local machine and GitHub:

- [GitHub: Troubleshooting SSH](https://docs.github.com/en/authentication/troubleshooting-ssh)
- [GitHub: Troubleshooting connectivity problems](https://docs.github.com/en/get-started/using-github/troubleshooting-connectivity-problems)

## Transit errors

The commit is on GitHub, but no deployment shows up in the dashboard:

- Is the [fortrabbit GitHub App](/1.platform/06.deployment/02.github-app.md) installed for the account or organization that owns the repo?
- Did the push go to the branch connected to the environment?
- Is the [deployment trigger](/1.platform/06.deployment/05.trigger.md) set to push to deploy? With manual deployment, pushes never deploy.
- Is the [deployment permission](/1.platform/06.deployment/18.permission.md) set to connected developers only? Then a push from a GitHub account without a developer connection is skipped without notice.

## Deployment errors

A deployment shows up in the dashboard, but it failed. The [deploy log](/1.platform/06.deployment/17.logs.md) names the failed command. A failed build leaves the previous code live, a failed [post deploy command](/1.platform/06.deployment/04.post-deploy-commands.md) comes after the new code went live. A [deploy file](/1.platform/06.deployment/06.deploy-file.md) with an error fails the deployment before the build.
