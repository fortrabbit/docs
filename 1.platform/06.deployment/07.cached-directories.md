## Dependencies kept between deployments

The [build commands](/1.platform/06.deployment/03.build-commands.md) usually include `composer install` or `npm install`, which fill the `vendor` and `node_modules` folders. A cached directory stays in the deployment service after the build, so the next build only fetches what changed. The first deployment takes longest.

The cache lives in the deployment service, not in the environment. Whether a cached folder also reaches the environment depends on the [exclude patterns](/1.platform/06.deployment/10.exclude-patterns.md).

Paths start at the Git repository root. A leading slash is optional, so `/vendor/symfony` and `vendor/symfony` are equivalent. `vendor` matches the root directory and all subdirectories.

## Default settings

```plain
node_modules
vendor
.pnpm-store
```

The [software template](/1.platform/03.concepts/05.software-templates.md) can set others. To turn caching off, save an empty value.

## Purging cached directories

Purge the cache when a build keeps failing on a broken dependency, for example after an interrupted install. The purge button in the deployment settings marks the cache for deletion: the next deployment starts with empty folders and builds a new cache.
