## How build commands work

Build commands are a list of commands that will get executed after the [fortrabbit GitHub app](/1.platform/06.deployment/02.github-app.md) has received the latest updates from Git and before those are deployed into the web space of the environment. The Git updates, together with the results from the build steps are forming the build package to be released with a [deployment](/1.platform/06.deployment/01.intro.md).

Commands run in order from the Git repository root. Use `cd` to change directory for that and all following commands.

## Automatic configuration

When setting up an app or environment, the fortrabbit GitHub app will use the stack detector to detect and autoconfigure all deployment settings, including build commands. Predefined [software templates](/1.platform/03.concepts/05.software-templates.md) and detection are combined. The most basic auto detected build commands are:

- When `composer.json` file is detected, `composer install` will run.
- When `package.json` is discovered `npm run prod` will run.

## Composer build commands

Most backend PHP development is done with the help of frameworks or content management systems. These are usually installed as a dependency and themselves using other dependencies. All that code is not part of Git, so when the code gets delivered, those dependencies need to be installed or updated for the given environment. The PHP dependency manager Composer is pre-installed. Find more details with our [Composer article](/3.dev/15.learn/02.composer.md). The default build command for most PHP frameworks is:

```bash
composer install --no-dev --prefer-dist --no-interaction --no-ansi --no-progress
```

## Node.js build commands

Most frontend web dev is done with the help of JavaScript build tooling. Node.js production build commands create build bundles to be served to clients from the web application.

```bash
npm install
npm run build
```

### Keep node_modules out of the deployment

The `node_modules` folder is a [cached directory](/1.platform/06.deployment/07.cached-directories.md): it stays in the build between deployments, so `npm install` doesn't download everything again. The app rarely needs it at runtime. Most software templates set `/node_modules` as an [exclude pattern](/1.platform/06.deployment/10.exclude-patterns.md), so it doesn't land in the web storage. Check that pattern when the app was set up without a template. Adding the pattern later doesn't remove a copy that was deployed before.

### Approve install scripts with npm 12

npm 12 blocks the install scripts of dependencies until they are approved. Some packages fetch or link their native binary in such a script, and the build then fails, for example with `lightningcss: line 1: This: command not found`. Approve those packages with npm 12 and commit the `allowScripts` block it writes to `package.json`:

```shell
$ npm install-scripts approve --no-allow-scripts-pin lightningcss-cli
```

Without `--no-allow-scripts-pin`, the approval is pinned to the installed version, and the next update of the package fails again.

When the build already failed, [purge the cached directories](/1.platform/06.deployment/07.cached-directories.md#purging-cached-directories) once after committing the approval. The failed build left the package in the cached `node_modules` folder without its binary, and `npm install` skips it until its version changes.

### Limits of the build

- `npm install` also installs the `devDependencies`, where build tools like Vite usually sit.
- npm and pnpm are installed, yarn and Bun are not. Install them as project dependencies. Bun also needs its install script approved.
- Global installs with `npm install -g` fail. Install tools as project dependencies instead: `./node_modules/.bin` is in the `PATH` of the build commands.
- Only known binaries can run. Headless browsers, like the one Playwright downloads, can't start.

## Yarn build commands

Yarn is not pre-installed and there are multiple versions out there. Install it via npm first, then run your yarn commands:

```bash
npm i yarn
yarn install
yarn build
```
