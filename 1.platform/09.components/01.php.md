## Booking

Choose the PHP plan when creating an [app](/1.platform/10.objects/01.app.md) or an environment, and change it later on the components page of the environment.

## Configuration

The [PHP settings](/1.platform/07.settings/06.php.md) of each [environment](/1.platform/10.objects/02.environment.md) set the version, extensions and ini values. The [metrics](/1.platform/07.settings/30.metrics.md) and [logs](/1.platform/07.settings/25.logs.md) show how PHP performs.

## Scaling

PHP plans differ in memory and in the number of PHP processes. Start small and scale when the metrics ask for it: PHP memory near the plan line, OOM kills, or [503 errors](/3.dev/22.http-status-codes/503.md) when all processes are busy. See [PHP processes](/3.dev/02.performance/06.php-processes.md).

### Autoscaling

PHP does not autoscale. A traffic peak or a slow script would otherwise set the bill, so the PHP plan stays where it is booked.

### Starting points

XS and SM cover most websites. Starting points from experience:

| Software                         | PHP memory |
| -------------------------------- | ---------: |
| Craft CMS, October CMS           |    512 MiB |
| WordPress, Kirby, Grav, Statamic |    256 MiB |
| Laravel, Filament                |    256 MiB |

The real need depends on visitors, plugins, configuration and custom code, see the [performance section](/3.dev/02.performance/index.md).

## MySQL connections for PHP

The PHP plan sets the number of [MySQL](/1.platform/09.components/02.mysql.md) connections: one per PHP process, plus some for jobs and database clients.
