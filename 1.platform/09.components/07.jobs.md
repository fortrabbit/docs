Jobs is an optional [component](/1.platform/03.concepts/03.components.md), booked and scaled per [environment](/1.platform/10.objects/02.environment.md). Higher plans add memory and more jobs.

```raw
┌─────────┐                        ┌──────────────┐      ┌─────────────┐
│ visitor │ ◀─ Request/response ─▶ │  environment │ ◀──▶ │ worker/cron │
└─────────┘                        └──────────────┘      └─────────────┘
```

Jobs run in their own container, with the same file system, [database](/1.platform/09.components/02.mysql.md), ENV vars and settings as the environment. Heavy work in a job does not slow down the web requests.

## Job types

- [Workers](/1.platform/30.jobs/03.workers.md) run non-stop, for example to process a queue.
- [Crons](/1.platform/30.jobs/02.crons.md) run on a schedule.

[Laravel](/2.guides/2.laravel/index.md), [Symfony](/2.guides/7.more/08.symfony.md), [Craft CMS](/2.guides/3.craft-cms/index.md) and [Statamic](/2.guides/5.statamic/index.md) all use queues and schedules. Set up jobs in the dashboard, see [jobs usage](/1.platform/30.jobs/01.usage.md).

## Scaling

The jobs memory and jobs processes [metrics](/1.platform/26.metrics/01.intro.md) show whether the plan fits. All jobs share the memory of the plan, see [jobs tuning](/1.platform/30.jobs/05.tuning.md).

## Performance

Signs that jobs need attention:

- Crons overlap because runs do not finish in time
- Jobs are killed for lack of memory

Before scaling up, check the code and the schedules.

## Extended binaries

These tools are installed for jobs only, not for web requests or SSH:

- ffmpeg
- Chromium and ChromeDriver
- Ghostscript
- cwebp and other WebP tools
- jpegoptim, optipng, pngquant, gifsicle
- brotli
