Backups are an optional scalable component available per environment in various plans. They include file and database backups, see [working with backup files](/1.platform/25.backups/files.md). The encrypted backups are stored off-site on Amazon S3 object storage and do not count towards your [storage](03.storage.md) usage. Backups can be downloaded from the dashboard, [backup restore](/1.platform/25.backups/restore.md) is offered too.

The number of backups created depends on your plan size, see [backup retention](/1.platform/25.backups/retention.md). The [backup schedule](/1.platform/25.backups/retention.md) will start after booking. The first daily backup will become available the next day. On the next Monday, the weekly backup spot will be filled. On the first of the month the monthly backup will be stored.

## Backup details for audits

The details an auditor asks for, for example under ISO 22301 or ISO 27001. Those standards set no backup schedule or retention period. The audited company defines its own recovery objectives and shows that the backups meet them.

| Question | Answer |
| -- | -- |
| Scope | Files on the file system and a `mysqldump` of the database, when the [database component](02.mysql.md) is booked. Some cache and log paths are left out, see [excludes](/1.platform/25.backups/files.md#excludes). |
| Unit | One backup set per [environment](/1.platform/10.objects/02.environment.md). Production and staging are backed up separately, each with its own plan. |
| Type | Full. Every backup is a complete file archive plus a complete database dump. No incremental or differential backups, no point-in-time recovery. |
| Frequency | One automatic backup every 24 hours. Manual backups can be added from the dashboard. |
| Retention | Set by the booked plan, see [backup retention](/1.platform/25.backups/retention.md). |
| Storage location | Object storage in the region of the [app](/1.platform/10.objects/01.app.md). Backups stay in that region. |
| Restore | Self-service from the dashboard, see [restore from backup](/1.platform/25.backups/restore.md). Takes from a few minutes to hours, depending on the size of the environment. No committed recovery time. |
| Monitoring | fortrabbit monitors the backup jobs and is alerted on failures. Users receive no success or failure notifications. |
| Last backup | The backups section of an environment in the dashboard lists every stored backup with date and size, plus the time of the next scheduled one. |
