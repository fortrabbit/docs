## Apps and environments

fortrabbit maps a web project in two layers:

- [App](/1.platform/10.objects/01.app.md): Git repo, [collaboration](/1.platform/20.collaboration/1.intro.md).
- [Environment](/1.platform/10.objects/02.environment.md): Runtime, git branch, code access, [components](/1.platform/03.concepts/03.components.md), settings.

## Workflows

One structure is recommended. The others work, with downsides:

### Projects as apps, environments are stages

```raw
- App: 'My website project'
  - Environment 1: 'Main' - live production
  - Environment 2: 'Dev' - feature development (optional)
```

Use environments as versions of the website. When using [git deployment](/1.platform/06.deployment/01.intro.md), branches can be mapped to environments. See the [multi staging article](/3.dev/15.learn/03.staging-environments.md). Each app requires at least one environment. One app with one environment is also common.

Rating: ✅ ✅ ✅ ✅

### Projects as folders in an environment

```raw
- App: 'My agency'
  - Environment 1: 'Main'
    - Folders: 'website-1', 'website-2' …
```

Several projects share one environment, each in a folder. Routing domains to the folders needs `.htaccess`, and the projects share the database and the PHP processes. Multi-site features of a CMS work the same way. Separate installations are easier to scale and to hand over.

Rating: ❌ ❌ ✅ ✅

### Project parts as environments

```raw
- App: 'website-1'
  - Environment 1: 'frontend'
  - Environment 2: 'backend'
```

Environments map to parts of a web project. This may work for [headless CMS systems](/3.dev/15.learn/05.headless.md), where frontend and backend are separated software.

Rating: ❌ ❌ ✅ ✅

### Projects as environments

```raw
- App: 'My agency'
  - Environment 1: 'website-1'
  - Environment 2: 'website-2'
  - Environment 3: 'website-3'
```

Each project gets an environment of one app. Access is granted per app, so a collaborator sees every project, and the projects share one Git repo.

Rating: ❌ ❌ ❌ ✅

### Projects as apps, stages as folders

```raw
- App: 'website-1'
  - Environment 1: 'Main'
    - Folders: 'prod', 'staging'
```

Stages live as folders in one environment. A deployment or a heavy job on staging slows production down, and both share the database.

Rating: ❌ ❌ ❌ ✅
