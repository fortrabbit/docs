When an app is created with [Git deployment](/1.platform/06.deployment/02.github-app.md), the [stack detector](/1.platform/03.concepts/04.stack-detector.md) picks the template from the code. Without Git, or when nothing is detected, choose the software in the dashboard. A template sets, per major version:

- The [root path](/1.platform/07.settings/12.root-path.md)
- [ENV vars](/1.platform/07.settings/01.env-vars.md) in the names the software expects, for example for the database connection
- [Build commands](/1.platform/06.deployment/03.build-commands.md) and [post deploy commands](/1.platform/06.deployment/04.post-deploy-commands.md)
- The [deployment strategy](/1.platform/06.deployment/08.strategy.md) with exclude and replace patterns

Software configured by [ENV vars](/3.dev/19.env-vars/01.intro.md), like [Laravel](/2.guides/2.laravel/index.md) or [Craft CMS](/2.guides/3.craft-cms/index.md), runs with these settings right away.

## What it does not do

A software template **does not install** the software. Install it with Composer in a [local development environment](/4.integrations/01.local-development/01.intro.md), or bring an existing project.

## All software templates

One block per major version, as the platform applies it. Software that names no settings of its own deploys with the platform defaults.
