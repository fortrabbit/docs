## Why develop locally

Develop and test on your own computer, then deploy. Running updates directly on the live server breaks the site for visitors when something goes wrong.

- See code changes right away
- Debug with dev flags turned on
- Test updates before they go live
- Keep a full copy of the project, independent of the host

## Requirements

The local stack should roughly match the fortrabbit environment:

- **Apache**: fortrabbit runs Apache, so `.htaccess` rules work the same locally. NGINX works too, but ignores `.htaccess`.
- **MySQL**: the database
- **PHP**: keep the major and minor version in sync with the environment, see [PHP version](/3.dev/20.how-to/upgrade-php.md)
- **Git**: version control, see the [Git intro](/3.dev/15.learn/git-intro.md)
- **Composer**: PHP dependencies, see the [Composer intro](/3.dev/15.learn/02.composer.md)
- **Node.js** and npm: frontend builds

## Container based

Containers keep the stack apart from the host system and can be shared across a team with the project. They need a Docker provider such as Docker Desktop or OrbStack.

- **[DDEV](/4.integrations/01.local-development/02.ddev.md)** (recommended): Docker setup for most PHP frameworks and CMS
- **[Laravel Sail](/4.integrations/01.local-development/05.laravel-sail.md)**: the Docker setup that ships with Laravel
- **Docker**: own `docker-compose.yml`, most control, most configuration

## Native apps

These run PHP and a web server directly on the host system. They start faster and use less memory than containers.

- **[Laravel Herd](/4.integrations/01.local-development/04.laravel-herd.md)**: macOS and Windows
- **[Laravel Valet](/4.integrations/01.local-development/03.laravel-valet.md)**: macOS, command line
- **[ServBay](/4.integrations/01.local-development/06.servbay.md)**: macOS and Windows
- **[Laragon](/4.integrations/01.local-development/07.laragon.md)**: Windows
- **[MAMP](https://www.mamp.info)** and **[XAMPP](https://www.apachefriends.org/)**: classic Apache stacks without Git and Composer

## PHP built-in server

For a quick test, PHP comes with a built-in web server. It ignores `.htaccess` and is not meant for production parity.

```bash
php -S localhost:8000

# Laravel wraps it
php artisan serve
```

A flat-file CMS such as Kirby runs with PHP alone, without a database.
