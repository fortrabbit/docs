## About GitHub

GitHub, owned by Microsoft, hosts Git repositories with pull requests, issues and CI. Git is the version control system, GitHub hosts it, see the [Git intro](/3.dev/15.learn/git-intro.md).

## Pricing

GitHub Free includes unlimited public and private repositories, see [GitHub pricing](https://github.com/pricing). fortrabbit charges nothing for the integration.

## Built-in GitHub integration

The [fortrabbit GitHub App](/1.platform/06.deployment/02.github-app.md) connects repositories to apps and deploys on every push. The [stack detector](/1.platform/03.concepts/04.stack-detector.md) and the [software templates](/1.platform/03.concepts/05.software-templates.md) preset the [build commands](/1.platform/06.deployment/03.build-commands.md) and [post deploy commands](/1.platform/06.deployment/04.post-deploy-commands.md). See the [deployment intro](/1.platform/06.deployment/01.intro.md).

## Using GitHub Actions

[GitHub Actions](https://github.com/features/actions) runs tests and builds on GitHub. Two ways to combine it with fortrabbit:

- Keep the GitHub App, and let a workflow call a [deploy hook](/1.platform/06.deployment/16.deploy-hook.md) once the tests pass, with the [deployment trigger](/1.platform/06.deployment/05.trigger.md) set to manual.
- Build in the workflow and copy the result with [rsync](/3.dev/20.how-to/rsync.md) over SSH. Set the [deployment trigger](/1.platform/06.deployment/05.trigger.md) to manual, so pushes do not also deploy through the GitHub App. The [blog post on GitHub Actions](https://blog.fortrabbit.com/how-to-use-github-actions) has two templates.

## Provide GitHub Actions code access

The rsync route needs SSH access. Use a key pair of its own: the public key as a [deploy key](/1.platform/10.objects/12.ssh-key.md#deploy-keys) of the environment, the private key as a secret in GitHub.

1. On your local machine, generate a dedicated key pair:
   `ssh-keygen -t ed25519 -f /tmp/key-github -N ""`
2. In the dashboard, add the **public key** (`/tmp/key-github.pub`) as a deploy key in the SSH keys settings of the environment.
3. On GitHub, go to the repository → Settings → Secrets and variables → Actions and add a new secret named `SSH_PRIVATE_KEY` with the contents of the **private key** (`/tmp/key-github`).
4. Delete both key files from `/tmp` once done.

### Example: deploy via rsync

This workflow builds assets with Node.js, installs Composer dependencies, and deploys the result to fortrabbit via rsync.

**.github/workflows/deploy.yml:**

```yaml
name: Deploy to fortrabbit
on:
  push:
    branches:
      - main
jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    env:
      DESTINATION: '{{app-env-id}}@ssh.{{region}}.frbit.app'
    steps:
      - uses: actions/checkout@v4

      - name: Set up SSH
        uses: webfactory/ssh-agent@v0.9.0
        with:
          ssh-private-key: ${{ secrets.SSH_PRIVATE_KEY }}

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version-file: 'package.json'

      - name: Install Node dependencies and build
        run: |
          npm ci
          npm run build

      - name: Remove source assets
        run: rm -rf <your-source-assets-folder>

      # Install PHP dependencies
      - name: Install Composer dependencies
        run: |
          composer validate
          composer install --prefer-dist --no-dev --no-progress --optimize-autoloader --ignore-platform-reqs
      # Deploy
      - name: Deploy via rsync
        run: |
          rsync -azh -e 'ssh -o StrictHostKeyChecking=no' \
            ./ \
            --rsync-path='rsync' \
            $DESTINATION:~/
```

- `DESTINATION` is the SSH address of the environment, shown in the dashboard.
- `StrictHostKeyChecking=no` skips the host key check. To check it, add the host key of fortrabbit to `known_hosts` in the workflow instead.
