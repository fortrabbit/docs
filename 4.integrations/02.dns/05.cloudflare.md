## About Cloudflare

Cloudflare runs DNS and a proxy in front of websites. It caches content like a CDN and filters attacks, including DDoS.

## Pricing and signup

Cloudflare has a free plan, see [Cloudflare plans](https://www.cloudflare.com/plans/).

## Integrating Cloudflare with fortrabbit

Cloudflare and fortrabbit have no direct connection. The name servers of the domain point to Cloudflare, which answers DNS and proxies the requests to fortrabbit.

### Setup Cloudflare

1. Add the domain to the environment in the fortrabbit dashboard.
2. Point it to fortrabbit at the current DNS provider, see the [external domain setup](/1.platform/13.domains/04.external-domain-setup.md).
3. Add the domain to Cloudflare, which imports the existing records.
4. Switch the name servers of the domain to Cloudflare at the registrar.

For a domain registered with Cloudflare, enter the records from the fortrabbit dashboard in Cloudflare directly.

### SSL/TLS encryption mode

The SSL/TLS settings of Cloudflare set how Cloudflare connects to fortrabbit. The visitor to Cloudflare is encrypted either way, the connection from Cloudflare to fortrabbit depends on the mode:

```
┌──────┐       ┌────────────┐             ┌────────────┐
│ User ├─HTTPS─▶ Cloudflare ├─ ? HTTPS ? ─▶ fortrabbit │
└──────┘       └────────────┘             └────────────┘
```

Set the mode to **Full**. fortrabbit serves the domain over HTTPS, so the whole way is encrypted. **Flexible** connects to fortrabbit over plain HTTP, which fortrabbit redirects to HTTPS, so the browser ends in a redirect loop.

## Advanced topics

### Domain status in the dashboard

With the Cloudflare proxy on, DNS returns Cloudflare addresses instead of the records for fortrabbit. The dashboard recognizes them and shows "DNS points to Cloudflare" instead of checking the records.

### Certificates without Cloudflare

fortrabbit provides free [TLS certificates](/1.platform/13.domains/06.https.md) for every domain. Cloudflare is not needed for HTTPS.

### Cloudflare and 2nd level subdomains

The free Cloudflare certificate covers the domain and one level of subdomains. A deeper subdomain like `dev.www.example.com` fails with `SSL_ERROR_NO_CYPHER_OVERLAP`, see [Cloudflare SSL troubleshooting](https://developers.cloudflare.com/ssl/troubleshooting/).

### Other reasons to use Cloudflare

- DDoS protection and bot filtering
- CNAME Flattening for [apex domains](/1.platform/13.domains/07.apex-domains.md)
- Caching of static files close to the visitor

### Prevent direct access

DDoS protection only holds when nothing reaches fortrabbit around Cloudflare, including the default domain. Allow only the Cloudflare addresses in `.htaccess`. fortrabbit passes the visitor address to Apache, here the Cloudflare one. ## Alternatives to Cloudflare

Cloudflare bundles DNS, proxy and CDN, and the website depends on all of them. Some clients prefer separate services for DNS and CDN.
