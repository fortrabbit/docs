## Misconfiguration

Configuration errors are among the most common causes of performance issues. Development settings in production, missing caching or conflicting plugins can slow down a live app. These problems often go unnoticed during testing but surface immediately when deployed with real traffic and data volumes.

- All assets are generated again with each deployment or even each page load. [Cached directories](/1.platform/06.deployment/07.cached-directories.md) keep `vendor` and `node_modules` between deployments
- The production environment runs in development or debug mode
- A plugin creates a ton of load or conflicts with other config
- Slow MySQL queries, see [database performance tips](/3.dev/02.performance/08.database.md)

## External sources

Applications depend on external APIs, CDNs, payment processors and other services. When one of them slows down, every request that waits for it slows down too.

- A third party service is down or slow

## Data threshold reached

Apps that perform well with test data can hit performance walls with real-world data volumes. Queries that are fast with hundreds of records become slow with hundreds of thousands.

- A MySQL query that is fast locally with little testing data, is slow in production

## Usage patterns changed

Visitor traffic and bot activity change over time. Spikes, new workflows or aggressive crawling expose bottlenecks that were not visible before.

- A website was linked from a popular blog and gets more visits
- A new user is uploading images of a larger size
- Bots crawl every page, including endless filter and search URLs
