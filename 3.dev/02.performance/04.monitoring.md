## Experience website speed yourself

Performance issues manifest as:

- Pages that load slowly with the browser loading icon spinning
- [504 timeout errors](/3.dev/22.http-status-codes/504.md) appearing on screen

## Check the browser dev tools

Browser dev tools show whether the time goes to the frontend or the backend. Open the network tab first: a long wait for the first HTML response is backend time, a large transfer total is page weight, see [reduce page weight](/3.dev/02.performance/09.page-weight.md). A Lighthouse audit points to rendering and JavaScript issues.

## Check the hosting metrics

The [metrics](/1.platform/26.metrics/01.intro.md) of an environment in the dashboard show the backend side:

- **[PHP response time](/1.platform/26.metrics/05.php.md#php-response-time)**: The chart marks below 150 ms as fast, below 350 ms as good and 700 ms as slow. A site with a high average breaks down sooner when more visitors arrive, see [504 errors](/3.dev/22.http-status-codes/504.md).
- **[HTTP errors](/1.platform/26.metrics/07.errors.md)**: A peak of 5xx errors together with a rising PHP response time points to 504 timeouts.
- **Memory**: Should stay clear of the plan's memory line on average, with room for peaks, for [PHP](/1.platform/26.metrics/05.php.md#php-memory) and for [jobs](/1.platform/26.metrics/06.jobs.md#jobs-memory).
- **[OOM kills](/1.platform/26.metrics/05.php.md#oom-kills)**: Should stay at zero. Each one is a process killed for lack of memory, see [out of memory](/3.dev/02.performance/10.out-of-memory.md).
- **[OPcache](/1.platform/26.metrics/05.php.md#php-opcache)**: Should not max out, see [keep OPcache below full](/3.dev/02.performance/05.backend.md#keep-opcache-below-full).

Once you've identified problematic metrics, see [common performance issues](/3.dev/02.performance/03.common-issues.md) for diagnosis steps, or review [backend performance best practices](/3.dev/02.performance/05.backend.md) for optimization strategies.
