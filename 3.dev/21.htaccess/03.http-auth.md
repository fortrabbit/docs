## Dashboard or .htaccess

| Need | Use |
| -- | -- |
| Lock a whole staging environment | Dashboard [password protection](/1.platform/07.settings/03.password-protection.md) |
| Protect one folder, such as `/admin` | `.htaccess` |
| Several users with their own passwords | `.htaccess` |
| Protection that follows the code into every environment | `.htaccess` |

Both use the same Apache module. While the dashboard password protection is on, Apache does not allow `AuthType`, `AuthUserFile` and `Require` in `.htaccess`, and a file containing them answers with a `500` error. Use one or the other.

## Create the .htpasswd file

The `.htpasswd` file holds one line per user: the username, a colon and the password hash. Create it locally with the `htpasswd` tool that ships with Apache:

```shell
htpasswd -c .htpasswd john
```

The tool asks for the password. `-c` creates the file; leave it out to add a user to an existing file. The result looks like this:

```raw
john:$apr1$jw6nGOHx$f/HpoNv9thNMd6w35Ttl80
```

Store the file outside the [root path](/1.platform/07.settings/12.root-path.md), so it is never served. With a root path like `public` or `web`, put it at the top of the `www` folder, at `/data/www/.htpasswd`. When the environment serves `www` itself, set a root path below it first. Apache never serves files starting with `.ht`, but a file outside the root path stays safe even when that rule changes.

## Create the .htaccess file

Add these lines to the `.htaccess` of the folder to protect, or to the one in the root path for the whole site:

```apache [.htaccess]
AuthType Basic
AuthName "Restricted area"
AuthUserFile /data/www/.htpasswd
Require valid-user
```

| Line | Does |
| -- | -- |
| `AuthType Basic` | Turns on HTTP basic auth |
| `AuthName` | Names the protected area |
| `AuthUserFile` | Absolute path to the `.htpasswd` file |
| `Require valid-user` | Lets in every user from the file |

## Deploy the files

Commit both files and deploy with [git](/1.platform/06.deployment/01.intro.md), or upload them with [SFTP](/1.platform/05.code-access/04.sftp.md). A `.htpasswd` in git stores the password hashes in the repository. To keep them out, upload the file once with SFTP or [SSH](/1.platform/05.code-access/03.ssh.md). The merge [deployment strategy](/1.platform/06.deployment/08.strategy.md) leaves it in place; with the replace strategy, add it to the exclude patterns.

## Protect only one environment

A `.htaccess` file in git reaches every environment. To ask for a password only on staging, wrap the lines in a condition on the environment name:

```apache [.htaccess]
<If "env('FORTRABBIT_ENVIRONMENT_NAME') == 'staging'">
  AuthType Basic
  AuthName "Restricted area"
  AuthUserFile /data/www/.htpasswd
  Require valid-user
</If>
```

See [environment detection](/3.dev/21.htaccess/05.environment-detection.md) for how this works.

## Basic auth and the app

Apache checks the password before the request reaches PHP. The browser then sends the credentials in the `Authorization` header with every request. An app that expects its own `Authorization: Bearer` token needs that token in a different header while the protection is on.
