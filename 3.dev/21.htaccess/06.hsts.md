## Set the header

Add this to the `.htaccess` in the [root path](/1.platform/07.settings/12.root-path.md):

```apache [.htaccess]
<IfModule mod_headers.c>
  Header always set Strict-Transport-Security "max-age=31536000"
</IfModule>
```

`max-age` is in seconds; `31536000` is one year. The platform's [HTTP to HTTPS redirect](/3.dev/21.htaccess/02.redirects.md) still answers the very first request, before the browser has seen the header. With HSTS, later requests skip that redirect and a downgrade attack has no unencrypted request to intercept. See [HTTP Strict Transport Security](https://en.wikipedia.org/wiki/HTTP_Strict_Transport_Security).

## What it locks in

A browser that saw the header uses HTTPS for the domain until `max-age` runs out, even when the site later serves `http://` again. Removing the header does not undo that for visitors who already have it.

| Option | Effect |
| -- | -- |
| `max-age=300` | Five minutes; a safe value for a first test |
| `includeSubDomains` | Also covers every subdomain, including ones on other hosts without HTTPS |
| `preload` | Asks to be added to the browsers' built-in list, see [hstspreload.org](https://hstspreload.org/); removal takes months |

Start with a short `max-age`, raise it once all pages work over HTTPS, and add `includeSubDomains` only when every subdomain has a certificate. More [HTTP headers](/3.dev/21.htaccess/12.http-headers.md) work the same way.
