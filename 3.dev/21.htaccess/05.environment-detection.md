## ENV vars in Apache

Apache gets the same [ENV vars](/1.platform/07.settings/01.env-vars.md) as PHP: the custom ones from the dashboard and the platform ones such as `FORTRABBIT_ENVIRONMENT_NAME`, which holds the name of the environment as it reads in the dashboard, for example `production`. A change in the dashboard takes about 60 seconds to reach Apache.

## Apply rules in one environment

The `<If>` block takes an [Apache expression](https://httpd.apache.org/docs/2.4/expr.html). `env()` reads an ENV var:

```apache [.htaccess]
<If "env('FORTRABBIT_ENVIRONMENT_NAME') != 'production'">
  Header set X-Robots-Tag "noindex"
</If>
```

This keeps search engines away from every environment except production. The condition reads the name as it shows in the dashboard. Locally, the variable is not set, so `!=` is true there as well.

## Use a custom ENV var

A custom ENV var decouples the rule from the environment name. Set it in the dashboard:

:BlockLink{title="Edit ENV vars for {{app-name}} / {{app-env-name}}" path="/environments/{{app-env-id}}/env-vars"}

```shell
PROTECT_SITE=true
```

Then check it in `.htaccess`, here for [HTTP auth](/3.dev/21.htaccess/03.http-auth.md) on a staging environment:

```apache [.htaccess]
<If "env('PROTECT_SITE') == 'true'">
  AuthType Basic
  AuthName "Restricted area"
  AuthUserFile /data/www/.htpasswd
  Require valid-user
</If>
```

## In RewriteCond

`mod_rewrite` reads ENV vars with `%{ENV:…}`. This redirects the [default domain](/1.platform/13.domains/01.default-domain.md) to the primary domain in production only:

```apache [.htaccess]
RewriteEngine On
RewriteCond %{ENV:FORTRABBIT_ENVIRONMENT_NAME} =production
RewriteCond %{HTTP_HOST} \.frbit\.app$ [NC]
RewriteRule ^ https://www.example.com%{REQUEST_URI} [R=301,L]
```
