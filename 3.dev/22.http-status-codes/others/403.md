## Common causes

| Cause | Check |
| -- | -- |
| No code deployed, or no `index.php` or `index.html` in the root path | Apache does not list folder contents, so an empty root path answers 403. Look into the folder with [SSH](/1.platform/05.code-access/03.ssh.md) or [SFTP](/1.platform/05.code-access/04.sftp.md) |
| Wrong root path | The [root path](/1.platform/07.settings/12.root-path.md) must point to the folder with `index.php`, such as `public` or `web` |
| An access rule | A `Require`, `Deny` or `RewriteRule … [F]` line in `.htaccess`, see [block IPs](/3.dev/21.htaccess/08.block-ip.md) |
| A protected file | Apache never serves `.ht*` and `.user.ini` files |
| The incoming firewall | With the [incoming firewall (WAF)](/1.platform/07.settings/20.firewall-incoming.md) on, it blocks requests that match its rules, which can include a software installer |
| File permissions | The files must be readable for their owner. SSH, SFTP and PHP all run as the same user, so `chmod -R u+rwX www` fixes a file that a tool set to `000` |

A request without valid credentials for a password-protected area gets a `401`, not a `403`. See [password protection](/1.platform/07.settings/03.password-protection.md).

## Apache error log

The Apache error log in the [logs](/1.platform/07.settings/25.logs.md) names the cause:

- [`AH01630`](/3.dev/15.learn/apache-errors.md#ah01630-client-denied-by-server-configuration): an access rule denied the request
- `AH01276 Cannot serve directory`: no index file in the folder

See [Apache error codes](/3.dev/15.learn/apache-errors.md) for the full list.
