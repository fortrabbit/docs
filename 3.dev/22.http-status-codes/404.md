## Common causes

| Cause | Check |
| -- | -- |
| No code deployed | Log in with [SSH](/1.platform/05.code-access/03.ssh.md) or [SFTP](/1.platform/05.code-access/04.sftp.md) and look into the `www` folder |
| Wrong root path | Compare the [root path](/1.platform/07.settings/12.root-path.md) setting with the folder that holds `index.php`, such as `public` or `web` |
| Files in an extra folder | Upload into `www` directly, not into `www/my-project` |
| `.htaccess` missing | Only the homepage works, every other page is a 404. The hidden file was left out of an SFTP upload or the git repository |
| Typo in the address | Check the URL in the address bar |

A framework or CMS answers its own 404 for routes it does not know. That page has the app's design; the fortrabbit 404 page means Apache found no file and no rewrite rule sent the request to `index.php`.

## Apache error log

The Apache error log in the [logs](/1.platform/07.settings/25.logs.md) names the cause with an `AHxxxxx` code. Behind a 404, look for [`AH00128`](/3.dev/15.learn/apache-errors.md#ah00128-file-does-not-exist): no file at the requested path under the root path. See [Apache error codes](/3.dev/15.learn/apache-errors.md) for the full list.

## Platform status

When the code and the root path are right, check the [fortrabbit status page](https://fortrabbit.betteruptime.com/) for incidents.
