## Read the logs

Open the [logs](/1.platform/07.settings/25.logs.md) of the environment and reload the failing page. The PHP log holds fatal errors with file and line. The Apache error log names the cause with an `AHxxxxx` code:

| Code | Cause |
| -- | -- |
| [`AH01071`](/3.dev/15.learn/apache-errors.md#ah01071-php-fpm-error-output) | PHP printed a fatal error, quoted in the log line |
| [`AH00124`](/3.dev/15.learn/apache-errors.md#ah00124-request-exceeded-the-limit-of-internal-redirects) | A rewrite loop in `.htaccess` |
| `Invalid command` or `not allowed here` | A directive `.htaccess` may not use, see [.htaccess troubleshooting](/3.dev/21.htaccess/10.troubleshooting.md) |

A 500 on every page right after a change to `.htaccess` points to the file itself: Apache rejects the whole file for one bad line.

## Review the latest changes

A 500 usually follows a deployment, an update or a changed setting. Run the same code in the [local development environment](/4.integrations/01.local-development/01.intro.md) and compare. Typical differences on fortrabbit: a missing [ENV var](/1.platform/07.settings/01.env-vars.md), a PHP extension that is off, or a different [PHP version](/1.platform/07.settings/06.php.md).

Many frameworks hide the error details in production. Laravel's `APP_DEBUG` and Craft's `CRAFT_DEV_MODE` show them; turn them on only on an environment that is not public.

## Platform status

When the logs show nothing, check the [fortrabbit status page](https://fortrabbit.betteruptime.com/) for incidents.
