## Why ENV vars

An app runs in at least two places: a [local development environment](/4.integrations/01.local-development/01.intro.md) and an environment on fortrabbit. Both have a database, with different credentials. The config files are in git, shared with the team, and must not contain the production password.

ENV vars solve this. An ENV var is a key-value pair, such as `DB_PASSWORD=sCRAmblEDegGGs`, set outside the code. The code reads the key, and each environment supplies its own value.

- **Security**: secrets stay out of the repository, see [ENV var security](/3.dev/19.env-vars/20.security.md).
- **Portability**: the same code runs locally, on staging and in production.
- **Team work**: each developer keeps their own local values.

## ENV vars on fortrabbit

Locally, a [.env file](/3.dev/19.env-vars/15.dotenv.md) holds the values. On fortrabbit, set them in the [ENV vars settings](/1.platform/07.settings/01.env-vars.md) of the environment. To read them in code, see [read environment variables in PHP](/3.dev/19.env-vars/10.access.md).
