## About SSH keys

An SSH key pair logs in without a password. The private key stays on the local machine, the public key goes into the fortrabbit account. fortrabbit uses SSH keys for [SSH](/1.platform/05.code-access/03.ssh.md), [SFTP](/1.platform/05.code-access/04.sftp.md), [rsync](/3.dev/20.how-to/rsync.md) and scp.

```shell
~/.ssh/
├── id_ed25519        # private key, keep it secret
└── id_ed25519.pub    # public key, add it to fortrabbit
```

## Check for an existing key

```shell
ls ~/.ssh
```

A pair like `id_ed25519` and `id_ed25519.pub`, or the older `id_rsa` and `id_rsa.pub`, can be used. Then [add the public key to the account](/1.platform/10.objects/12.ssh-key.md).

## Create a key pair

```shell
ssh-keygen -t ed25519 -C "me@fortrabbit"
```

The `-C` comment only labels the key, use any text. Set a passphrase when asked, and store it in the system keychain or a password manager. Then copy the public key and add it to the account:

```shell
cat ~/.ssh/id_ed25519.pub
```

## Use a specific key

When the key is not in the default location, name it:

```shell
ssh -i ~/.ssh/other_key {{app-env-id}}@ssh.{{region}}.frbit.app
```

## Windows

Windows 10 and 11 ship OpenSSH: run the same `ssh-keygen` command in PowerShell or in Git Bash from the [official Git installer](https://git-scm.com/downloads). Keys created with PuTTY use their own format and need converting before `ssh` and `git` can use them, so create the key with `ssh-keygen`.
