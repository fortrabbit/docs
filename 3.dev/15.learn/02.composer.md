## Composer in the deployment

[Composer](https://getcomposer.org) installs the PHP dependencies listed in `composer.json`, in the exact versions locked in `composer.lock`. On fortrabbit, `composer install` runs as a [build command](/1.platform/06.deployment/03.build-commands.md) with every git deployment, in a separate build container. The installed `vendor` folder then goes live with the code.

The stack detector adds the command when the repository has a `composer.json`:

```shell
composer install --no-dev --prefer-dist --no-interaction --no-ansi --no-progress
```

## Composer and git

- Commit `composer.json` and `composer.lock`.
- Keep `vendor` out of git with an entry in `.gitignore`.
- Both files sit in the folder that gets deployed: the repository root, or the [git source directory](/1.platform/06.deployment/09.git-source-directory.md) in a monorepo.

Run `composer update` locally, test, and commit the new `composer.lock`. The deployment installs exactly those versions.

## Composer over SSH

`composer install` also runs over [SSH](/1.platform/05.code-access/03.ssh.md), for example after an [SFTP](/1.platform/05.code-access/04.sftp.md) upload without git. It then runs in the environment itself, with the memory of the PHP plan. Never run `composer update` there: it resolves all versions from scratch, needs much more memory and changes the versions without testing.
