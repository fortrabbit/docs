## About monorepos

A monorepo stores several related projects in one git repository, often with shared dependencies and releases in step:

```raw
monorepo
 - packages (shared)
 - app-1
 - app-2
```

Tools such as Turborepo or Nx manage the shared parts, see [monorepo.tools](https://monorepo.tools/). Monorepos are common in JavaScript, less so in PHP. fortrabbit's own frontend is a JavaScript monorepo.

A web project with a JavaScript frontend and a PHP backend in one repository works the same way, see [headless workflows](/3.dev/15.learn/05.headless.md).

## Monorepos on fortrabbit

[Git deployment](/1.platform/06.deployment/01.intro.md) is built around one repository per project, and handles a monorepo with these settings per environment:

- [Git source directory](/1.platform/06.deployment/09.git-source-directory.md): the folder that gets deployed, for example `/apps/website-1`
- [Build commands](/1.platform/06.deployment/03.build-commands.md): run from the repository root, so a build step can reach the shared packages before it changes into the project folder
- Branch and automatic deployment: connect the same repository and branch to several environments

An environment cannot deploy from several repositories, and git submodules and subtrees are not supported.

## CMS multi-site

Craft CMS, Kirby, WordPress and Statamic can run several sites from one installation. That is an alternative to a monorepo when the sites share content and templates. See [project organization](/1.platform/02.get-started/01.project-organization.md) for the trade-offs.

## External pipelines

A CI service such as [GitHub Actions](/4.integrations/03.git-providers/02.github.md#using-github-actions) can build the project and upload it with rsync over SSH, authenticated with a [deploy key](/3.dev/15.learn/01.ssh-key-setup.md#deploy-keys).
