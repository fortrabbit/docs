## About staging environments

A staging environment runs the next version of a site next to production, for testing and sign-off before go-live. On fortrabbit, an [app](/1.platform/10.objects/01.app.md) holds several [environments](/1.platform/10.objects/02.environment.md), each with its own domain, database, ENV vars and Git branch.

For a small site, a [local development environment](/4.integrations/01.local-development/01.intro.md) and production can be enough.

## Common setups

- **staging + production**: changes go to staging first, get tested, then move to production. The usual setup for client projects with sign-off.
- **temporary + production**: an extra environment for a redesign or a major upgrade, deleted afterwards.
- **development + staging + production**: development holds the latest changes, staging is for quality assurance, production is live. For teams with continuous integration.

## Branches and environments

With [Git deployment](/1.platform/06.deployment/01.intro.md), each environment follows its own branch, such as `develop` for staging and `main` for production. A merge into a branch deploys that environment. See the [GitHub App](/1.platform/06.deployment/02.github-app.md).

## Configuration per environment

Frameworks and CMS read the stage from an [ENV var](/3.dev/19.env-vars/01.intro.md), such as `APP_ENV` in Laravel or `CRAFT_ENVIRONMENT` in Craft CMS. Set different values per environment in the dashboard: database credentials, mail settings, API keys for test accounts.

## Data between environments

Code moves up with Git, but databases and uploads stay in each environment. To test with current content, copy production data to staging:

- Database: export from production and import into staging, see [MySQL export and import](/1.platform/08.mysql/02.export-import/07.intro.md).
- Uploads: download with [rsync](/3.dev/20.how-to/rsync.md) from production and upload to staging.

Never copy staging data into production without a plan: content created on production in the meantime gets lost.
